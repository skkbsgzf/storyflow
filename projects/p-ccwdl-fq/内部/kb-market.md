# 生产约束基线

**用途**：选题分析报告第五节"创作约束移交单"的默认数值来源——约束不再拍脑袋，直接取市场实盘（7938 部在售剧本的硬格式统计）。方案对这些条款逐条对账（`kb/aesthetic/oversight` 监理纪律，违反一票否决）。

## 一、体量约束（分布即标准）

| 维度 | 主流值 | 分布依据 |
| --- | --- | --- |
| 集数 | **60 集**（4224 部） | 50 集 945 / 80 集 925 / 40 集 718 / 30 集 116 |
| 单集时长 | **1-1.5 分钟** | 竖屏付费短剧口径 |
| 单集字数上限 | **1200 字**（4284 部） | 1000 字 1640 / 1400 字 528 / 1600 字 476 |
| 场景数上限 | **≤3**（7937/7938） | 几乎全库硬约束——低成本快转景 |
| 主要演员上限 | **≤10**（7925 部） | 同上 |

**用法**：方案默认按 60 集 × 1.5 分钟 × 1200 字 × ≤3 场景 × ≤10 演员声明约束；偏离主流值（如 80 集或 4 场景）必须在移交单中显式声明并给理由——偏离不是错，隐式偏离才是错。

## 二、约束 → 编排的直接推论

1. **3 场景上限** ⇒ 每集冲突必须发生在可复用景（宅门/办公室/宫殿/车厢）；换景 = 换集节拍点。剧情编排师分集时先画场景复用表。
2. **10 演员上限** ⇒ 有名有姓角色 ≤10（含反派）；群演反应拍（当众打脸必需）不计入，但"全场惊呆"必须由环境描写的群演承担。
3. **1-1.5 分钟 ≈ 600-900 字正文**（script-drama-beat 口径）⇒ 每集 8-12 拍，前 3 秒钩子约 1 拍、结尾卡点约 2 拍。
4. **60 集 × 1.5 分钟 = 90 分钟总片长** ⇒ 实际叙事容量 ≈ 一部电影的紧凑版：主线只容 1 个大反转 + 2-3 个中型反转（`kb/aesthetic/reversal` 结构位点联动），副线必须挂主线条件。

## 三、题材标签纪律

申报题材标签从市场受控词表取（快照 `genreHeatCN`/`genreHeatNA` 中的 genre 字段），不用自造词；标签组合 = 1 主题材 + 2-3 副标签（市场策划案通行形），标签顺序即卖点顺序。

## 四、与硬断言的绑定

本条目数值进入约束移交单后，由 minitool `check_contract_compliance` 逐条对账；分拍格式合规由 `AE-BEAT-FORMAT` 断言扫描（`kb/aesthetic/assertions.json`）。

# 设定体系约束（世界观代入成本红线）

**命题：短剧/漫剧的观众没有耐心学一套新世界观。** 点子再好，架构没有厚度——读者无法快速代入理解——就是废案。世界观的代入成本是选题阶段的一票项，不是成稿阶段再优化的细节。

## 一、设定来源三级制

| 级别 | 来源 | 判定 |
| --- | --- | --- |
| **首选** | **实事新闻做底子**：防汛救灾、工程质量清查、债务与烂尾、养老与医疗、裁员与再就业——全民共识的公共事件，零解释成本，主旋律有锚 | ✅ 直接可用 |
| **次选** | **市面验证过的设定体系做创新改编**：战神归来/赘婿/重生/系统/马甲/先婚后爱等——观众已被市场教会规则，创新只做变体不做体系 | ✅ 可用，须挂竞品对标 |
| **禁止** | **原创科幻/架空世界观**：自造中台/异能体系/架空王朝规则等需要观众先学后看的设定 | ❌ 一票否决 |

## 二、判定方法：三分钟测试

- 【block】**三分钟测试**：路人观众开播 3 分钟内，在不依赖任何设定解释的前提下，能否说出"这是谁、他想要什么、为什么替他急"？凡需要先讲设定才能进冲突的开局 = 违反本约束。
- 【major】设定词密度：前三章正文中的**自造专名**（体系名/组织名/规则名）≤2 个；超过即代入成本超标。
- 【major】实事锚点：选题理由必须至少引用一条**当月公共议题/新闻方向**作为情绪底（与 zeitgeist 步联动），架空设定天然缺此锚。

## 三、正确的"创新"位置

约束禁止的是**世界观层原创**，不禁止创意：创新发生在①**人物关系与身份层**（不确定因素注入：黑道大小姐/真假千金/穿书/初版作者）；②**结构改造**（`kb/structure/catalog` 三步）；③**实事底子上的具体事件**。好点子要长在观众熟悉的土壤上——点子的锐度 × 土壤的熟悉度 = 代入速度。

## 四、执行接线

- S1 调研：约束移交单新增 **C10 设定体系约束**（本条目），选题方向必须声明设定来源级别。
- S2 结构：框架案的世界观节按三级制声明来源；原创倾向在此拦截。
- R1/R2 红方：三分钟测试 + 设定词密度为固定检查项（`kb/aesthetic/perspective-review` 一般读者视角主责）。

# 梗密度与发散性约束

**命题：选题阶段是全流程的网感输入源。** 选题产出的梗与素材要喂给后续所有阶段（结构/方案/剧本/传播切片）；梗的传播度和密度不足，后续每一层都会"无趣"——这不是文案问题，是资源储量问题。

## 一、S1 产出硬指标

| 指标 | 要求 |
| --- | --- |
| **网络热梗素材表** | S1 梗卡必须附带 ≥10 条与题材相关的**现存高传播梗**（每条：梗名/来源与传播度评级/可挂接的场景示例） |
| **发散性** | 每个主梗/新变体须可拆出 ≥3 个跨场景可复用的梗用法（对话梗/场面梗/切片梗）——只在一个场景成立的梗不算储量 |
| **密度自查** | 前三章每集至少 1 处可独立切片传播的"梗点"（观众能截出来转发的东西） |

## 二、梗词典数据源（纳入数据库的输入源清单）

| 源 | 类型 | 用途 |
| --- | --- | --- |
| 小鸡词典（含镜像存档） | 梗词典 | 梗的出处、演变、用法 |
| 梗百科 / 萌娘百科 | 百科类 | 梗的条目化解释与传播链 |
| B 站热梗榜 / 抖音话题榜 | 平台热榜 | 当期传播度实测 |
| 知乎"网络流行语"相关高赞 | 语义讨论 | 梗的语义漂移与代际差异 |
| 微博热搜 / 百度指数 | 传播度实测 | 评级数据源 |

接入方式：`meme_harvest` minitool（待实现，规格：抓取/清洗/去重/传播度评级 → 产出 `梗素材表` 增量并入 KB）；实现前由调研步人工按上表整理，**梗素材表仍为 S1 必交付**。

## 三、与既有约束的关系

- 梗密度约束**不替代** C10 设定约束（`kb/market/setting-rules`）：梗要密度，设定要低代入成本，两条红线并行。
- 题材选择本身受梗密度约束**反向影响**：同等条件下，优先选**梗储量高的领域**（如国球/职场/校园——全民梗库富矿），放弃梗荒领域（例：无公共记忆的架空科幻）。

# 题材解剖学（素材聚合与关系逆位选题法）

**命题：选题调研的目的不是收集素材，是扒出题材背后的关系结构。** 热梗、热搜、事件都只是大众的声音（现象层）；声音背后是几方人马稳定的权力关系（结构层）。梗是结构的分泌物——不解剖结构就收集梗，收上来的是一堆装饰品，这就是「假材料」。

## 一、四层剥离（申论式，逐层往下，不许跳层）

| 层 | 问什么 | 产出 |
| --- | --- | --- |
| 现象层 | 发生了什么（一句话，去形容词） | 事件时间线 |
| 利益层 | 每个参与方要什么（流量/生意/情绪/安全——用他们自己的算盘说话） | 各方收益-代价表 |
| 权力层 | 谁对谁有什么权力，权力怎么行使、代价是什么 | 权力线清单 |
| 结构层 | 这个题材的本质隐喻是什么（卡牌塔/燃料库/祭司——好隐喻=读者三秒懂的权力关系） | 一句话本质 |

## 二、关系结构（三~五方，两两画线）

- 参与方用**角色化命名**（主播/吃瓜群众/商家），不用抽象名词（意见领袖/消费者）；
- 两两之间画权力线：A→B 有什么权力（框架权/定罪权/生杀权/供养权/收买权），B 拿什么换、怎么忍；
- **不对称点标红**：权力即时 vs 反制慢速、成本零 vs 代价全额——不对称最锐利处 = 最疼处 = 爽点矿脉。

## 三、逆位生成（爽点从关系倒置中来）

对每条权力线只问一句：**如果位子反过来呢？**

- 「主播有框架权」逆位 → 主角有透视权 / 框架权易主 / 框架权带毒（每用一次反噬+1）；
- 「口碑是易碎卡牌塔」逆位 → 口碑是可视可控的数值系统（卡牌塔有了仪表盘）；
- 「群众是燃料」逆位 → 群众是法官 / 群众是主角的武器库 / 主角是执火人。

每个逆位写成一个方向候选（金手指 / 关系轴 / 爽点机制三行），选最有写头的 2-3 个进选题报告。**爽点清单必须能回指到某条被逆的权力线——回指不了的爽点是套路复写，不是这个题材长出来的。**

## 四、材料落位原则（素材的正作用凭证）

| 素材/梗 | 结构位（谁/哪条权力线） | 消费点（机制位/场面梗/台词梗/世界观位） |
| --- | --- | --- |

- 每个素材**必须落位**：说得出它服务于谁、哪条权力线、被消费在方案的哪个实处；
- 落不了位的素材删除——留在报告里而没有消费点的材料都是装饰品，装饰品冒充深度 = 假材料；
- 落位表是选题报告的必备节：它正面回答「搜集这么多素材服务于啥」。

## 五、题材类型适配（流程灵活性依据）

| 题材类型 | 解剖步骤 | 素材来源 |
| --- | --- | --- |
| **现实映射**（职场/都市/商战/舆论等现实底题材） | 全流程必跑：四层剥离→关系结构→逆位→落位 | 实时热点 + 事件档案 + 梗底座 |
| **模板文**（无限流/修仙/穿越/系统等非现实映射） | **可整体跳过**：直接走 kb/trope 梗族饱和度选型 + kb/aesthetic 结构标准 | 梗族结构库 + 对标件；实时热点仅作调味可选 |

- 判据：题材的冲突动力是否来自现实关系（职场权力/舆论场/阶层）——是则解剖；冲突动力来自自足的规则系统（副本规则/修炼体系/系统面板）则模板文路线，关系结构由世界观自建（此时解剖对象换成「题材模板的权力结构」，如无限流的「队内关系」、修仙的「宗门资源链」）。
- 配置落点：项目配置.json 的「题材类型」（现实映射/模板文）+ flow 输入 zeitgeist 开关——模板文置 false，跳过实时解剖节点，调研步直接消费 kb/trope。

# 单元剧网文结构标准（多故事集合体 · 暗线先行）

**命题：网文不是一部电影，是一座电视台。** 编剧流程讲一个故事（三幕/五节点/60集一杠到底）；现代网文是**多故事集合体**——用有趣的设定和世界观把一串单元故事串起来连载。两者的流程重心完全不同，禁止套用编剧结构。

## 一、三层结构（主次纪律）

| 层 | 装什么 | 要求 |
| --- | --- | --- |
| **世界观（底座）** | 力量体系、势力与矛盾、主角力量来源与代价、世界规则 | **必须扎实，暗线先行**——人物有了动机，做啥都合理且有趣；主线平一点问题不大，底座塌了全塌 |
| **暗线（主线）** | 力量来源之谜、世界观级悬念、长线矛盾 | 平铺慢推：节点藏好、定期抖一格；不追求每章推进 |
| **单元剧（明线）** | 一串自成故事的小单元（抹黑平反/打脸/副本/事件） | **每单元必须炸**：自成起承转合 + 状态增量（世界观认知/关系/实力至少动一项）+ 梗点密度 |

- **选题阶段分清主次**：选题产出的是「好梗集合 + 世界观种子 + 单元剧素材库」，**不锁具体主线故事**——发现的素材（如大模型/思维链/哈内丝这种素材量爆炸的好梗）细化后与调研融合即可；具体事件（如某次抹黑风波）只是一个单元剧的候选，不是主线。
- 单元剧素材库是流动资产：随时补充（每单元收尾时顺手登记下一个候选），主线暗线节点从库里挑大的挂。

## 二、流程映射（与编剧流程的差异）

| 阶段 | 编剧流程 | 网文流程（本标准） |
| --- | --- | --- |
| 选题 | 找一个故事方向 | **发散聚合**：好梗集合 + 世界观种子 + 单元剧素材库（发散性强，分清主次） |
| 开书 | 八段式策划案/三层问答锁故事 | **先搞世界观**（力量体系/矛盾/力量来源/规则清单 → wiki 化 RAG）；人物动机从世界观长出来 |
| 大纲 | 重型：三幕×分集功能×卡点表 | **轻量**：暗线节点表 + 单元剧序列 + 首批单元细纲，完事 |
| 成稿 | 台词/镜头精度 | **五问**：人设立得住吗 / 冲突自然吗 / 梗多吗 / 节目效果足吗 / 有没有AI味 |

## 三、世界观 wiki（RAG 纪律）

- 世界观产出双件：**世界观圣经.md**（人读，叙述性）+ **世界观/ wiki 目录**（机器可检索）；
- wiki 条目 = 独立 md 文件 + frontmatter（id/title/tags/links），条目间 `[[id]]` 交叉链接；`世界观/index.json` 为词条索引（RAG 入口），大纲/成稿/打磨节点开工先查索引、按 tags 取词条；
- 设定一律词条化：**每个设定可被独立引用**（写第 47 章时只需拉出相关 3 个词条，不用重读圣经全文）；
- 词条状态机：draft（设定中）/ active（已进正文）/ retired（被版本更新推翻——世界观的迭代本身可以是剧情）。

## 四、成稿五问（大纲→小说的质量重心）

1. **人设立得住吗**：动机从世界观长出来（不是编剧硬安）；行为可预测（读者能替他做决定）；
2. **冲突自然吗**：冲突从势力张力线和神格差异里长出来，不是巧合堆的；
3. **梗多吗**：每章 ≥1 可切片梗点；梗进对话进情境；
4. **节目效果足吗**：每章至少一个「可截屏发群里」的场面/台词；
5. **有没有AI味**：结构级去机味（ai-trace 五指纹 + fastfood 红线），终稿过三遍法。

## 五、判定条款

1. 【block】世界观未 wiki 化（无 index.json 词条索引）→ 大纲/成稿节点不得派发；
2. 【major】单元剧结尾无状态增量 → 单元不算完成，退回细纲；
3. 【major】暗线连续 10 章零推进 → 判沙漠段，下一单元必须挂暗线节点；
4. 【minor】选题报告锁定单一主线故事 → 违反发散原则，退回重写主次划分。

# 快餐抽象网文形态标准（番茄线）

**标尺**：快餐抽象是长篇网文的极限档——读者在通勤/蹲坑/睡前刷完一章，笑点密度优先于世界观体量。判定单位是"章"，商业单位是"追读与完读率"。母标准（`kb/formats/webnovel-longform`）全部适用，本条目只叠加收紧项。

## 一、章节形态

| 项 | 约束 | 说明 |
| --- | --- | --- |
| 章长 | 1500-2400 字 | 手机 5-8 分钟读完；超 2400 必须拆章（爆点章可到 2800，不许灌水凑长） |
| 入戏 | 每章前 300 字必须进事件 | 第一章前 100 字必须出现反常；禁止开章写景/回顾上章 |
| 段落 | 1-3 行为主，全章 ≥1 个单句成段 | 大段（>5 行）全章 ≤2 处；段落参差本身是节奏 |
| 章末钩子 | 强制（收束四型轮换） | 快餐线钩型配比：信息反转/行动推进为主，连续同型判 major |
| 梗点 | 每章 ≥1 处可切片传播的梗点 | 梗点 = 读者能截图发群里的那句/那拍（AE-MEME-DENSITY 章级版） |

## 二、抽象梗纪律（快餐线的命）

1. **梗要"用"不要"提"**：热梗必须长进对话和情境里（人物真的会那么说话/那么做事），禁止解说式玩梗（"这就是传说中的 XX 梗"）。解说式玩梗判 major。
2. **梗失效测试**：每处用梗过一遍——把梗换成平实说法，情境本身还成立/还好笑吗？不成立 = 梗是拐杖，重写。热梗生命周期 2-8 周，情境底座决定成稿能否活过梗的热度。
3. **梗密度有地形**：对话和冲突峰值处堆梗，情绪真段落（哪怕快餐文也有）零梗——全是梗 = 没有呼吸，读者麻。
4. **抽象不等于瞎**：抽象是逻辑的意外拐弯（预期违背），不是没有逻辑。每个抽象桥段回看必须能说出"因为他是个 XX 的人所以会干这事"。

## 三、去AI味（番茄线硬约束）

- 朱雀类 AI 检测是**结构级**，词句层替换无效（`kb/aesthetic/ai-trace` 全表适用）；快餐文额外红线：
- **句长抖动**：连续 3 句等长判警；短句/独词句/断句是快餐文的天然掩护，但要有疏有密；
- **总分总绝迹**：不许"总的来说/综上所述/可以说"式收束段；章末只留钩子不留总结；
- **排比配额**：三连排比全章 ≤1 处；"不是……而是……"句式全章 ≤2 处；
- **口语脏东西**：语气词、口头禅、半截话、突然的短句——这些"不规整"是活人感来源，修订时不许磨平；
- 检测口径：过检测抽测以朱雀类参考信号为准，**参考信号不作目标函数**（防为过检而文风劣化）。

## 四、平台与商业语境（番茄）

- 免费阅读 + 广告分账：前 3 章决定推荐池位与追读，**前三章即试稿验收范围**；
- 更新节奏：快餐线日更 2-3 章，开书稿需存稿 ≥10 章——试稿通过后卷纲按此口径排产；
- 卡点：番茄章节卡点 = 每章末钩子（无付费墙压力），但每 8-12 章需一个"小高潮+悬念双押"的大卡点拉追读；
- 书名/简介：网感公式产出（`kb/market/internet-feel`），书名 ≤12 字带梗点或反差。

## 五、与 harness 的对应

- 快餐线 = 一条多阶段 flow：选题（热梗驱动）→ 开书（Bible 轻量版）→ 前三章章纲 → 逐章成稿 → 去AI味终稿；
- 逐章子图标准形状沿用 `kb/formats/webnovel-longform` §五：写前台账切片 → 写 → 过审 → 结算；
- 台账五类（人物状态/在场物品/知情范围/到期伏笔/长期承诺）开书即建，章章滚动（`kb/continuity/state-ledger`）。

# 长篇网文形态标准

**标尺**：网文长篇是**连载消费品**——判定单位是"章"，商业单位是"追读与稿费"。与短剧共用审美十二维度，但形态约束如下。

## 判定条款

1. **【block】章末钩子强制**：每章结尾必须留下悬念/转折/情绪钩（chinese-novelist-skill 纪律）。钩型轮换参照 `kb/deconstruct/style-learning` 收束四型——连续同型钩判 major（pacing 维度沙漠段的章级版）。
2. **【major】开书三层问答**（chinese-novelist-skill）：题材与核心情绪（对齐 `kb/deconstruct/protocol` 类型判断）→ 主角与金手指/核心欲望 → 前十 章事件链。三问没答完不开书。
3. **【major】批量生成节奏**：一次生成 10-50 章时，先出全段"章功能序列"再逐章执行——逐章流水式生成必然偏航（大纲偏离是 InkOS 审计 37 维之一）。每章交稿必过 `kb/continuity/state-ledger` 台账校验。
4. **【minor】题材画像先行**：开书前挂载对应题材画像（甜宠/追妻火葬场/虐恋/悬疑/重生/复仇/系统流……），画像含该类型的核心情绪走向与读者期待清单——`kb/deconstruct/protocol` 六槽位拆出的同类型对标件是画像的最佳来源。
5. **【minor】平台与商业语境**：星月写作路线的代表约束——目标平台规则（番茄等）、保底与全勤节奏、**过 AI 检测**（联动 `kb/aesthetic/ai-trace`：朱雀类检测是结构级，词句层规避无效）。模型选型影响产出质量档位，选型结论记入 flow 的模型参数，不入知识条目。

## 与 harness 的对应

- 长篇 = 一条多阶段 flow：开书（三层问答 → World Bible）→ 卷纲 → 章功能序列 → 逐章（写前台账切片注入 → 宿主写 → submit 过审计 → 状态结算）。InkOS 的"出草稿→过审计→按需修订→状态结算"四步即单章子图的标准形状。
- 批量生成时 flow 以"章"为原子任务包单位，断点续跑天然按章落盘（runtime 已有语义）。
