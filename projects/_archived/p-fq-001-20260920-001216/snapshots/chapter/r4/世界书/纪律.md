# 世界书纪律（更新机制·逆向 deepwrite）

> 来源注记：体系逆向自 `.refs/deepwrite` 长篇工作台——worldbuilding（list/text 双格式，`contentAuthority: files` 文件即真相）/ characters+continuity（人物分型 + 每章结算四件）/ plot（六阶段）。按 miniflow 的 md-first 约定落地，零数据库。

## 一、双格式

- **list 型**（人物/势力/地理/设定）：总览在 index.json，**一人一文件/一势力一文件**——文件即真相（contentAuthority: files），索引只是指针；
- **text 型**（底牌/大事记）：单文件整体维护。

## 二、人物分型（deepwrite 四型）

**主角 / 主要配角 / 次要配角 / 路人**——入场即建档：角色首次出场当章，写手待登记清单必须含其动机三行（要/怕/卡），宿主结算时建卡。路人若无升级预期不入卡（防百科化）。

## 三、章回结算五件（「不断更新」的执行点）

每章 flow_submit 之后、下一章派发之前，宿主按写手「待登记清单」结算：

| # | 结算件 | 写入处 | deepwrite 对应 |
| --- | --- | --- | --- |
| 1 | **章卡**：本章一句话+梗点+钩型+新名目 | 编年/章账.md 追加一节 | chapter card |
| 2 | **人物状态推进**：谁的状态变了（伤/钱/知情/关系/位置）→ 改人物卡「当前状态」段，变动摘要追加「变动史」 | 人物/*.md | characterState + history |
| 3 | **交接（handoff）**：下一章写手必须知道的 3-5 条（=章账末节「交接下一章」） | 编年/章账.md 末节 | handoff 文件 |
| 4 | **伏笔变动**：新埋/回收/顺期 → 伏笔/台账.md 表格更新（状态 open/paid/retired） | 伏笔/台账.md | foreshadowingChanges |
| 5 | **世界揭示**：本章确立了什么新设定事实 → 设定词条或编年追加（version+1，updated 改） | 设定/*.md、编年/大事记.md | worldReveals |
| 7 | **读者认知边界**：本章末「读者此刻知道/不知道」各 1-3 条记章账本节；本章新词落档 设定/名目与黑话.md 登记台账（首现章/读者已解章/说明手法）。断层双向：正文有而世界书无=断层；世界书有而读者未被介绍却当已知用=同罪 | 编年/章账.md、设定/名目与黑话.md | readerKnowledge |

## 三·五、结算第六件：快照（Diff 的数据底座）

结算五件落盘后，宿主用快照工具把**本行改动过的文件**（章账/人物卡/设定词条/伏笔台账）与**正文**留不可变快照：

```bash
python tools/snapshot.py capture <flow> <project> <node> --files "世界书/编年/章账.md,世界书/人物/陈潮生.md,正文-第001章.md"
```

工作台据此提供行级 Diff（世界书变了哪些 / 正文变了哪些）；无快照的文件不出现 Diff 按钮。

## 四、状态机与版本

- 词条状态：`draft（设定中）→ active（已进正文）→ retired（被推翻；不删，留档）`——**世界观的迭代本身可以成为剧情**（版本更新日设定即来源于此）；
- 每次修改：frontmatter `version` +1、`updated` 改当日；大改在词条末尾「变动史」记一行。

## 五、RAG 规则（写第 N 章的开工动作）

1. 读 `世界书/index.json`，按本章 tags 拉相关词条（写第 47 章只拉 3 个词条，不重读全书）；
2. 读 `编年/章账.md` **末节**（=上一章 handoff，含人物当前状态**与读者认知边界**）；
3. 读 `伏笔/台账.md` 中 status=open 且预定回收点临近的条目；
4. 底牌目录仅暗线节点需要时按节点号取对应段，禁止整读。

## 五·五、正文驱动补全（写到哪里、补到哪里）

RAG 不是只读的：**正文推进到哪，世界书就跟到哪**，防「agent 库库写、读者断层」。

- **写前准入**：本章细纲里的新名目/新人物，先在 设定/名目与黑话.md（或对应词条）登记为 draft，并定好首现说明手法（五手法之一，见文风档 §十二）；
- **写中即录**：写作中冒出的计划外新词，进「待登记清单」随稿提交，禁止用了就忘；
- **结算落档**：第七件把新词转正（draft→active），补「读者已解章/说明手法」；
- **断层自检**：结算时逐词核对——正文出现而台账没有的词，要么补写巧妙说明，要么改写掉；下一章写手以「读者认知边界」为准判断哪些词可直接用、哪些必须再说明。

## 六、禁区

- 正文不得出现 banned 词（词汇表.json）与底牌内容；
- 新名目/新人物：先登记（本索引+设定/名目与黑话）再进正文；
- 词条之间用 `[[id]]` 交叉链接；文件即真相，改文件不改索引=失效（结算时必须同步 index.json 的 status/version）。
