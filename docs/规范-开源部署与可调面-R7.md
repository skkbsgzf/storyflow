## 二 · 可调面总表（「能不能调」不再取决于常数写在哪一层）

分三层，**规则统一**：出厂默认 → 项目覆盖 → 节点/op 覆盖。**任一层都不许把默认值写死在代码里读不到的地方。**

### A · 已可调（现状，无需改造）

`op.config` 声明式旋钮（`resolveToolConfig`，`kits.ts:277`）：`depth` / `strictness` / `maxChars` / `model_tier`，
以及模块级专属项（`chapterMin`/`chapterMax`/`minScenes`/`passes`/`innerLoops`/`deadlineRounds`/`scale` 等）。
合成优先级：**`overlay.opConfig` > 节点 `config` > `op.default` > 通用默认**（`overlay.ts` 路径）；
`unknownKeys` 显式回显，不静默丢弃。

### B · 本波新增（OS-02 阶段 A 已接线，2026-09-20）

| 字段 | 位置 | 出厂默认 | 作用 | 落地 |
|---|---|---|---|---|
| `policy.maxRounds` | `flow.schema.json` `policy` | 不设上限（旧行为） | 单个 link 累计驳回上限；超限 → `blocked`（**停机等人，不再无限乒乓**） | `kernel.ts::doGate` link 分支 + `rejectCapped` |
| `policy.awaitTimeoutMs` | 同上 | 不设超时 | 等待态最长毫秒；到点 → `status=blocked` + `stalledAt`（**只标记不自动推进**） | `kernel.ts::markStalled`（`advance` 入口） |

两者对 **flow@2 / flow@3 同等生效**：`effectiveFlow` 此前只透传
`kit_boundary/gate_mode/adapt/budget`，`maxRounds`/`awaitTimeoutMs` 会被静默丢掉；
本批一并补上（flow@3 侧在 `POLICY_KEYS` 白名单里，早已透传）。

> 顺带解释了「`itb-` 门为什么能拦住人」之外的第二种失控：**连接件驳回没有上限**，
> 「驳回 → 重跑上游 → 再撞同一门 → 再驳回」可以无限循环，只有人肉盯得住。

## 三 · 模型档位（用户点名的「用高级模型」）

### 勘误 1：枚举冲突已修

| | 改造前 | 现在 |
|---|---|---|
| `contracts/module.schema.json` `definitions.tool.model_tier` | `["high","low"]` | **`["high","lite"]`** |
| `tools/module-lint.py` `TIERS` | `{"high","low"}` | **`{"high","lite"}`** |
| `core/src/kits.ts:251`（引擎） | `["high","lite"]` | `["high","lite"]` |

改造前：写 `low` **过 lint 但被引擎丢弃**；写 `lite` **过引擎但被 lint 报错** — 两条路都错。

### 勘误 2：默认值语义不一致（**OS-02 阶段 C 已落地，2026-09-20**）

| 声明处 | 改前 | 现在 |
|---|---|---|
| `contracts/module.schema.json` | 「缺省不声明 = 无档位约束」 | 不变（**契约措辞为准**） |
| `core/src/kits.ts` | `default: "high"`，`resolveToolConfig` 会回填 | **删掉 `default`**，且注入循环**跳过 `default === undefined` 的旋钮** ⇒ 未声明就真的不出现在 `values`/`sources` 里 |

⇒ 改前实际行为「用户不表态 = 系统自动上强档」，现改为 **不表态 = 不约束**。
消费侧随之对齐：`optimize.ts` R4「成本高可降 lite」只在**显式 `high`** 时才提（不许把「不约束」当 `high` 去降）；
R3「升到 high」在未约束或轻档时都提（那是**收紧**，低风险）。任务包新增「本步未约束的配置项」一节，
把「有旋钮但没表态」显式列出来，而不是静默按某个默认跑。

> 连带修的回归：`r5-generative.test.ts` 断言 `values`/`sources` 键集对称——`undefined` 默认值会被
> `JSON.stringify` 丢掉，造成「在 `sources` 里但不在 `values` 里」的错位。现未声明旋钮只活在 `defs` 里。

### 现状盘点（实测）

13 个 op 声明 `model_tier: "high"`，**零个声明 `low`/`lite`**：

```
modules/drama :: scene-breakdown
modules/prose :: layer-voices, layer-scenes, prose-assembler, novel-deai,
                 dialogue-polish, novel-judge        （7 个）
kits/prose    :: 同上 6 个
```

⇒ 本波把枚举从 `high|low` 改成 `high|lite` **对存量数据零影响**（无一处使用 `low`）。

## 四 · 初始化面板要读的声明面

面板**不新增契约**，只消费已有声明。四个分区各自的真源：

| 分区 | 数据源 | 现状问题 |

| 阈值预算区 | 本规范 §二 的 C 表 | ✅ **OS-02 阶段 C 已通**：`core/src/budget.ts::DEFAULT_BUDGET` 19 旋钮 → `effective.json` 的 `budget` 块 → 页面 `budgetZonePaper()` 逐键渲染（离线降级也显式说明）。**页面不自造旋钮**：page-lint 断言「渲染键集 == 内核 `defs` 键集」 |
| 门与风险区 | `policy.link_default` / `policy.maxRounds` / `policy.awaitTimeoutMs` / `itb-` 默认策略 | `maxRounds`/`awaitTimeoutMs` 本波刚冻结；`itb-` 默认已由 `always` → `auto`（OS-02A） |

**落盘目标**：`projects/<id>/项目配置.json`（契约 `contracts/project-config.schema.json`，
字段用中文键：`项目`/`题材`/`题材类型`/`创作目标`/`需求`/`灵感`/`严肃性`/… /`阈值预算`）。
面板的**项目输入区**与它是同一份数据 —— OS-04 已把「`flow.inputs` 逐字段表单」与「`项目配置.json` 中文键」对账
（`configToInputs` 直通 + 推导），不构成两份真源。

**阈值预算的合成链（OS-02 阶段 C，一个派生层、一个插入点，不新增优先级规则）**：

```
flow.policy.budget（模板层）
  ← 出厂 overlay（flows/<id>/overlay.default.json）
  ← 项目配置.json 的「阈值预算」（实例层；effectiveOf 造的派生层，origin:"kernel"，不落盘）
  ← 项目 overlay 的 set-policy{budget}（运行时调整层；对象值按 key 浅合并）
  → resolveBudget()（唯一一次派生）→ registry/effective.json 的 budget 块 → 页面纯消费
```

**消费链已通**：`flow.inputs` → `cond.ts:169 resolveInputs` → `state.inputs` → `kernel.ts:323/343`。
缺的只是**表单**，不是管道。

## 九 · OS-04 余量执行记录：项目配置模板库（2026-09-20 第五批）

§四已把「初始化面板要读的声明面」列清，并留了一个洞：**用户改好的配置存不下来、换项目用不了**。
本批补上这一层，并把它定成**内核能力而非页面逻辑**——理由与 §四 同源：一个事实只允许有一处实现。

### 规范：模板库的三条铁律

**① 两个根不同源，必须分开传。**
自存模板在**数据根**（`<root>/templates/项目配置/<flowId>/<名>.json`），官方示例在**仓库根**
（`<repoRoot>/demos/<flowId>/项目配置.json`）。任何把 `repoRoot` 缺省成 `dataRoot` 的写法，
都会让 `--root <tmp>` 下的官方示例**凭空消失**。内核 API 显式签名 `CfgTemplateScope{dataRoot, repoRoot}`。

**② 用户能改的错一律 4xx，不许当 500。**
| 情形 | 码 |
|---|---|
| 模板名非法（空 / 含路径分隔符 / 超 40 字） | `INVALID_INPUT` 400 |
| 项目无 `项目配置.json` / 模板不存在 | `NOT_FOUND` 404 |
| 同名模板已存在且未 `overwrite` | `CONFIG_EXISTS` 409 |
| 跨 flow 套用且未 `force` / 同名跨 flow 歧义 | `INVALID_INPUT` 400 |
| 尝试删除官方示例或「从零新建」 | `INVALID_INPUT` 400 |

把用户手误报成「服务器内部错误」，与「崩掉当没事」是同一种病。
实现上 `cfg-template.ts` 自带 `CfgTemplateError`（**不 import `kernel.ts`**：kernel 要 import 它落读模型，
反向引 `KernelError` 就成环），在 `verbs.ts` 边界映射成 `KernelError` ⇒ 三面拿到的仍是统一码。

**③ 诚实失败，不瞎猜。**
- 模板名在多个 flow 下都存在 ⇒ 报歧义并要求显式 `--flow`，**绝不「取第一个」**。
- 套用时 `项目` 键**一律改写成目标项目 id**（模板里记的是来源项目名，照抄会立刻触发内核一致性校验失败）。
- 坏模板文件进 `skipped` 如实回报，**不静默跳过**。

### 契约与读模型

| 面 | 落点 |
|---|---|
| 模板存储 | `<数据根>/templates/项目配置/<flowId>/<名>.json`（`文件名即模板名`，名字白名单不允许需转义的字符 ⇒ 无「悄悄改名」） |
| 内核模块 | `core/src/cfg-template.ts`：`listConfigTemplates` / `saveConfigTemplate` / `applyConfigTemplate` / `deleteConfigTemplate` / `cfgTemplate`（四动作分派） |
| 动词 | `verbs.ts::cfg_template`（`action` ∈ list/save/apply/delete；`project`/`name`/`flow`/`overwrite`/`force`）⇒ CLI、`POST /api/verbs/cfg_template`、MCP 三面同一实现 |
| 读模型 | `registry/config-templates.json`（`config-templates@1`，`persistEffective` 时落盘）；`viewLive` **每次现扫**并入 `configTemplates` 切片与 `revision` 指纹 |
| 页面 | 「项目配置模板库」区消费上述读模型；`tplVerb()` 是唯一动词入口；`applyLive` 就地回填 + 重渲染 |

**为什么 `viewLive` 要现扫而不是读落盘读模型**：模板是用户**随时会增删**的东西，而 `registry/*.json`
只在 `flow_effect` 时刷新。只读落盘件 ⇒ 面板会一直显示上一版清单，**那就是面板在撒谎**。
「运行状态类」允许滞后（由 run 驱动），「用户资产类」必须现读——这是本批新增的一条判据。
