## 〇、作者裁定（2026-10-11）—— 本工单的边界法律

原话：**「kit 提供知识，分镜提示词，描述，剧本，不参与真实绘制，但是能够对接生图引擎。具备识别加速模型，安排质量检测和重跑的能力。」**

这句裁决同时解掉了 `docs/ROADMAP.md:136`「纯粹化」与本工单的冲突（原 §五.0 的前置疑问），落成六条硬约束：

1. **绘制本体不在 kit。** kit 不持权重、不跑采样、不做算法、不承诺画面质量。像素一律由外部生图引擎产出。
2. **「对接」= 三层形态，全要：**
   - `image-job@1` 任务包是**事实源**（谁提交都得按它）；
   - kit **出参考驱动器**（`tools/img-drive.py`），默认可替宿主提交，文件头标注「可替换件」；
   - 驱动器只做**提交 / 轮询 / 取产物 / 记账**四件事，不做任何画面上判断。
3. **「识别加速模型」是明列新能力**，不是附带品：出厂 `presets/image/acceleration.json` 签名表 + `img-probe` 实测出收据（§四.1③）。
4. **质检三层全做**：确定性像素账（`img-check`）+ 显式「未检测项」清单 + 语义看图任务规格（交宿主 vision）+ 自包含审片页（语义终裁归人眼）。
5. **接线两步走**：先出 `modules/visual` 能力件挂进现有流并**恢复 `presets/comfyui-script` 的空 patches**；真机验证通过后再升独立 `flows/comic`。
6. **裁断归人、阈值不当闸**：数值只记账进复核清单，打回只来自确定性完整性或缺件（红线 4/5，与 ROADMAP T6 同源）。

> 由此：**视频维持冻结原判**（`docs/ROADMAP.md:100` 只对视频继续有效），本工单只申请**图像**解冻。

## 一、结论先行

1. **kit 的漫画能力现在只到文本层，图像层是一条包内私有 seam。**
   - 分镜 = 文本分镜剧本（`modules/drama/module.json:8-13`，产出 `分镜剧本.md`）；漫剧核数 = 字数与卡点存在性（`tools/manju-meter.py:1-12`）。
   - 唯一真生图件：`storyharness/packs/deduce/engine/deduce-images.ts:30-82`（comfyui）+ `:86-114`（dashscope）。它是**推演页立绘/背景的私产**：模型名写死 qwen（`:36-38`）、图结构硬拼在 TS 里、无参考图编辑链、无收据、无显存护栏、无批量/续跑。
   - `presets/comfyui-script/overlay.screenplay.json:5-6` 是空 patches 占位壳，`core/src/production-preset.ts:118` 只剩关键词路由。
2. **本工单就是 ROADMAP 在等的那个「明确场景」。** `docs/ROADMAP.md:101` 写的是「深度适配（真实 ComfyUI 工作流对接）**待明确场景另立工单**」——场景已由那轮实测给出，§〇 已完成改判，可以动手。
3. **普适性靠五件声明件，不靠把 qwen 的参数抄进 kit。** 后端画像（profile）／图模板（graph 声明件）／加速件签名表／任务包（job）／出图收据（receipt）。判断「这台机器这个模型能做什么」由 `img-probe` 实测出收据，不由代码假设。
4. **中间表示是 storyboard@1（分镜表）。** 那轮实测的立场已被会话自己钉死：「ComfyUI 是像素生成底座，不是漫画编排器；剧情→分镜→一致性策略→气泡→排版归脚本」。所以 kit 出的是**分镜表契约 + 出图任务包 + 看图证据件**，编排语义在声明面，裁决归人。
5. **六批推进，A 批零网络、零 core 改动。** A（契约+画像+图模板+`img-plan`）/ B（探测与驱动器）/ C（质检与重跑与审片页）/ D（语料卡+技能卡）/ E（声明面接线）/ F（三脸同源，可长期不做）。

## 三、现状盘点：有什么 / 缺什么

**有什么（可复用，别重写）**
- ComfyUI HTTP 三件套调用范式：`POST /prompt` → 轮询 `/history/{pid}` → `GET /view` 取字节，已在 `deduce-images.ts:47-79` 跑通；dashscope 异步任务范式在 `:91-113`。
- 确定性脚本壳进 flow 的机制：`module@1` 的 `script` op 由内核 spawn（`core/src/minitools.ts:71-146`），超时可按「节点 config > op config > 默认 60000ms」解析（`:117`，D#14），解释器走 `MINIFLOW_PYTHON`/`STORYFLOW_PYTHON`（`:124-127`），产物注册走 `makeArtifact`。`modules/base/module.json:132` 起有 10 个现役 script op 可照抄形状。
- **stdlib-only 纪律是硬规矩**（有先例有明文）：`tools/deconstruct.py:33`、`tools/diagnosis-validate.py:10`、`tools/diagnosis-page.py:82` 三条零依赖红线；`tools/_vendor/README.md` 立的是「依赖缺失 = 显式失败，不兜底」。新工具全部遵守，不引 PIL/requests/numpy。
- 收据惯例：`tools/quality-scan.py:94-122`（stdout 只出证据 + 收据文件路径回显，「无收据 = 删声明」）；机器区 `registry/receipts/<tool>-<node>.json`（`core/src/minitools.ts:375-377`）。
- 配置惯例：`.external/storyharness.json`（不入库）+ 包 manifest 声明键形态契约（`storyharness/packs/deduce/.storyharness.json:11-19`，现状 `extensions.deduce.image` 在 `.external/storyharness.json:10-13`）。
- 语料卡/技能卡编译链：`tools/kit-compile.py`（md → `kit/hypergraph.rag.json`）、`tools/kit-skills.py`（`skills/*.md` → `kit/skills.tools.json`）。
- 文本层上游件：`plot` 的剧本 IR、`drama` 的 `分镜剧本.md`、`skills/scene-breakdown.md`、`knowledge/formats/comic-drama-adapt.md`、`tools/manju-meter.py`。

**缺什么（要补的）**
- 没有分镜表（机读）契约，没有任务包（job）与出图收据契约。
- 没有后端画像/图模板/加速件签名表声明面——现在「用哪个模型、什么节点、能不能带参考图、有没有 turbo」全写在 TS 里。
- 没有出图执行件（批量、幂等续跑、串行、护栏、探测）。
- 没有图像类质检件（像素账、缺陷证据、重跑清单、审片页）。
- 没有漫画视觉语料（分格语法/气泡口径/一致性策略/缺陷规避），`knowledge/` 12 个域里零图像。
- 声明面没有视觉域：`modules/` 八个域（base/plot/prose/drama/search/delivery/plan/topic）里没有一个提供「出图」cap。
- `script` op 的输入被限制为「沿上游 BFS 找最近 **.md** 产物」（`core/src/minitools.ts:88-95`）——分镜表形态因此倾向「md 内嵌 json 块」，见 §五.1。

## 四、方案设计

### 4.1 五件声明件（普适性的落点）

**① `image-profile@1`（新契约 `contracts/image-profile.schema.json`）** — 「这台机器上这套模型怎么出图」：
```
backend: comfyui | openai-images | dashscope | off
base_url, 模型标识（unet/clip/vae 或 model id）, 量化档位（含 te_quant）
graph_template: presets/image/graphs/<name>.json 的相对路径
engines: { base: {steps,cfg,sampler,sigmas?,node_patch?}, turbo: {...} }   # 档位表，不写分支代码
capabilities: { reference_edit, in_model_text, negative_prompt, batch, transparent_bg }
budget: { max_pixels, vram_reserve_gb, cold_timeout_s }
style_prefix / negative_default                                    # 从 comic-run.py:27-31 外提
secrets: 只允许声明键名，值一律在 .external（红线：apiKey 不入库）
```
出厂 2–3 份画像（qwen-image-2.1-comfyui（实测形状）、generic-sdxl-comfyui（`CLIPTextEncode`+`KSampler` 通形）、api-openai-images），**用户可新增画像文件而不改代码**——这是「各种生图模型」的接口。

**② graph 模板 = 声明件**（`presets/image/graphs/*.json`，ComfyUI API-format + 槽位占位 `__PROMPT__`/`__NEG__`/`__REF_1__`/`__SEED__`/`__W__`/`__H__`/`__OUT_PREFIX__`）。
理由：qwen 的 `TextEncodeQwenImage21`（三输出：positive/negative/**latent**）与 SDXL 的 `CLIPTextEncode`+`IPAdapter` 图**不同形**，在代码里硬拼必漂移——现状 `deduce-images.ts:35-46` 就是一份硬拼副本，且和 `comic-run.py` 那份已经长得不一样了。图模板入库（零密钥），坑写在模板旁注里（例：`images` 是 autogrow，API 格式必须传嵌套字典 `{"image_1":[node,slot]}`，扁平键能过校验但执行期 TypeError——实测，`comic-run.py:78-89`）。

**③ `presets/image/acceleration.json`（加速件签名表）** — 「识别加速模型」的数据面，作者裁定的第 3 条落在这里：
```
entries[]: {
  name, provenance（在哪个组合上实测的，附收据路径）,
  detect: { lora_name_pattern, required_nodes[], model_pattern },
  engine_patch: { steps, cfg, sampler, sigmas?, node_patch? },
  memory_note, risks
}
```
`img-probe` 拿 `/object_info` + LoRA 目录清单比对签名，命中即回显「检测到 X，实测加速 Y×（来源：收据路径）」，**不自动启用**——启用要用户在 profile 的 `engines` 里点名。没命中的加速件不猜。

**④ `image-job@1`（新契约，**事实源**）** — 一批出图任务的可交换包：
```
profile 引用 / storyboard 引用
tasks[]: { task_id, path(anchor|page|panel), graph_template, engine, prompt(全文),
           negative, refs[](锚图/前格 + 文件路径), seed, size{w,h}, grid?,
           output_glob, depends_on[] }
policy: { concurrency: 1, timeout_s(按冷值), on_fail: "record", resume: true }
```
任何驱动器（kit 的参考件或宿主自己的）都按 job 提交；job 的 `tasks[]` 指纹（profile+template+prompt+seed+size）是幂等续跑与重跑判定的唯一依据。

**⑤ `image-receipt@1`（新契约）** — 每图一收据：`job_fingerprint`/`task_id`/`profile`/`backend`/`engine`/`accelerator`/`model`/`prompt`（全文）/`refs`/`seed`/`steps`/`cfg`/`size`/`seconds`/`prompt_id`/`files`/`vram_before`/`vram_after`/`at`。声明「已出 N 张 / 残留 M 处」不带收据路径即违规（红线 5）。

### 4.2 `storyboard@1`（新契约 `contracts/storyboard.schema.json`）

分镜表是 agent 认知步的产物、job 的输入、人审的对象：
```
project/flow/episode 绑定, style（画风声明，含色彩强度）, layout 默认（grid 2x2 / 逐格）
characters[]: { name, 锚描述, anchor 文件引用, 一致性策略 }
pages[]: { page_no, grid, panels[]: {
    panel_no, 画面描述, shot(机位/景别), bubbles[]: { speaker, text, 字数 },
    narration[]?, refs[]（锚图/前格）, engine, seed?, size?, bubble_mode?, status } }
```
每格 `bubbles[].text` 字数按 profile 的 `in_model_text` 口径**只出证据**（`img-check` 记账），不自动改稿。

### 4.2b 美术资产面（人设 / 背景 / 物品 / 细节图案）与产物管理

作者点名的四类设计资产与「产物管理」落在这里，两件契约 + 一件工具：

- **`asset-design@1`**（`contracts/asset-design.schema.json`）——设计意图件，落在 `美术资产表.md` 的内嵌 json 块（与分镜表同形态，同受 `minitools.ts:88-95` 只认 .md 的约束）。`assets[]` 每条带 `class ∈ {character, background, prop, detail}`、`intent`（一句设计意图）、`design`（按类分形的结构化字段：character 脸/发/服/色/体格 + `variants` 三视图；background 空间/光/天气/年代；prop 形制/材质/新旧；detail 纹样母题/线条性格/用途）、`refs`（引用其它资产 id 做合成，如服装纹样引用某 detail 资产）。**设计件里没有状态字段**——意图与产物状态分离，状态归台账。
- **`asset-registry@1`**（`contracts/asset-registry.schema.json`）——产物管理台账，由 `tools/img-assets.py` 从 `image-job@1` + 收据目录**确定性重建**（不是手写件，可反复重跑）。每条目：`asset_id` / `class` / `design_fingerprint` / `task_id` / `current{file,receipt,at,engine,seed}` / `history[]`（含废稿，移动归档不硬删）/ `status ∈ {ungenerated, generated, failed, needs_rerun, stale_design}`。`stale_design` = 设计件已改但产物仍是旧指纹（改了设定没重出图，这类「半接状态」必须点名）。
- 对账三张账缺一不可：`unresolved[]`（有任务无设计 / 有设计无任务 / 收据指向不存在的文件）、`summary.by_status`、台账 `note` 里的**不裁决声明**（台账只记账，好坏归人与 vision 复核）。

### 4.4 一致性是策略，不是流程

分镜表每格声明策略，按 profile 能力位择路（知识卡写规则，代码不写死）：
1. `reference_edit=true` → 锚图当 ref 走编辑链（默认，实测保身份，代价是轻微漂移）；
2. profile 挂了角色 LoRA 槽 → 用 LoRA 保一致性（这台机训不动，别的机器可以——留口不硬拒）；
3. 都没有 → 固定 seed + 结构化锚描述 + 每格全分辨率出再拼页（对应「每格像素不足」那条的解）。

### 4.5 气泡双轨（kit 只出规格，不出像素）

- `in_model_text=true` 且每句 ≤8 字 → 模型内直出（一步到位：构图+分格+气泡+中文），排版层零工作。
- 长对白 / `in_model_text=false` → 分镜表要求模型出**留白构图**（prompt 里显式留气泡位），把「文字后压」的意图交给宿主。**外置气泡排版规格件 `bubble-layout@1` 已按作者 2026-10-11 口径出账暂缓**（不在「现在要的产物」点名清单内）；分镜表 `bubbles[]` 只承载台词文本与说话人，不含坐标。无论哪条轨，**kit 都不贴字、不合成像素**。
- 分镜表每格可覆写 `bubble_mode`，缺省由 profile 决定——两条都是声明轨，默认自动择。

### 4.6 质检分层与 stdlib 天花板（诚实口径）

- **第一层（机器，可自动）**：像素账 + 齐全性 + 指纹一致性 → `img-check` 出证据。
- **第二层（语义，交宿主）**：`vision-review@1` 规格（字形是否正确、手/肢体是否崩、分镜时序是否读得通、角色是否同一人）→ kit **不自己判**，只把该问的问题写清楚。
- **第三层（人眼，终裁）**：审片页 + 收据 → `flow_gate`（pass / pass-with-conditions / send-back / reject），`flow_gate`/`set_decision`/`ig_*` 刻意不给机器（红线 4）。
- 天花板必须写明：stdlib 解不了 WebP/16-bit/调色板 PNG，也做不了 OCR、排版分析与结构检测 → 这些项**只进 `not_checked[]`**，不允许出现「已检查无问题」这类越界声明。

## 七、明确不做

- **kit 内不做绘制**：不持权重、不跑采样、不含生成算法、不承诺画面质量（§〇.1）。

- **暂缓（作者 2026-10-11「其他的暂不需要」）**：`bubble-layout@1` 外置气泡排版规格件、独立 `flows/comic`（先挂现有流）、F 批 `verbs.ts` 三脸同源。

- 不做常驻任务队列 / 自动重试循环（重跑只出清单，执行归人；长任务生命周期归宿主）。
- 不把本机模型名、盘符路径、apiKey 写进代码或提交；测试一律合成 fixture（`projects/` 与 `.external/` 不入库）。
- 不引第三方 Python 依赖（stdlib-only 纪律）。
- 不用数值线当隐形闸：像素/字数/显存阈值只出证据或显式失败要求人覆写旋钮。

## 八、继承的已知坑（写进 D 批语料卡的素材）

- ComfyUI 生产实例是嵌套目录 + 指定 venv 解释器（缺 `filelock` 的解释器起 `main.py` 直接崩）——**属用户环境问题，kit 不代管进程**，只在 `probe` 失败文案里给出排查要点。
- 本机 `python` 曾被 WindowsApps stub 劫持（rc=49 零输出，伪装成代码 bug）；本仓对策已存在：`MINIFLOW_PYTHON` 旋钮（`core/src/minitools.ts:124-127`）+ `scripts/ops/` 启动器注入。新工具**必须**吃这个旋钮，不许自己 `python`。
- CLI 脸冷启动税 ≈103s：出图这种分钟级任务若走 CLI 要考虑进程税，MCP/长驻宿主优先。
- 混排 GBK 输出：`PYTHONUTF8=1`/`PYTHONIOENCODING=utf-8`（`verbs.ts:113-128` 的 bridge 已带 utf-8 差量，新脚本 stdout 也必须显式 reconfigure）。
- **「半接状态」教训**（那轮实测的核心教训）：引擎不支持的能力必须**显式报错点名**，绝不能静默降参后出一批错图——静默降级是这批工作最贵的坑。
