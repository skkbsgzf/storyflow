## W4.1 · 项目看板聚合器 + 固定模板（P1，最大件）

**目标**：一条命令出全量自包含 HTML 看板——项目知识体系一页可见（KB 板块/簇、世界书、大事记、RAG 图谱、知识多维表格、产物文件区）。

**前置**：无（全部数据源已就绪：worldbook/journal/kb-graph/diagnosis 四生成器 + project-index + kit/hypergraph.rag.json）。

**任务分解**：
1. `tools/dashboard-template.html`：固定模板六区布局（左侧导航 + 主区 tab：总览/世界书/大事记/RAG 图谱/知识表格/产物），内嵌数据为惰性 JSON，零外部资源红线沿用
2. `tools/dashboard.py`：聚合器——调四个既有生成器取数据 + project-index + 知识多维表格数据（id/title/domain/track/status/version/tags/updated 从卡 frontmatter 提取）→ 单 HTML 落 `projects/<id>/dashboard.html`
3. 知识表格区：筛选（domain/track/status）+ 排序 + 搜索 + 点击看卡全文（内嵌数据，不回 call kit）
4. 产物区：只读文件清单（project-index human/generated 标注）+ 点击预览正文（读写通道见 W4.2）
5. 双根支持：`--project <id> [--root <父目录>]`（平铺回退同 kit-compile 口径）；梦核影子/外部根都能出板

## W4.2 · 产物读写三通道（P1）

**目标**：看板里对产物目录 md/txt 可读可编；doc 类只读预览。

**任务分解**：
1. 通道 A（本地，主力）：看板 HTML 经 **File System Access API**（Chrome/Edge）授权项目目录 → 直接读写盘上文件；模板内嵌 `showDirectoryPicker` 引导；Firefox/Safari 降级只读+下载
2. 通道 B（在线）：8431 既有 `/api/panel/files|raw|preview` 更名/封装为看板文件 API（鉴权走既有口令；**写通道需新增 PUT/PATCH**——写走临时区 + 确定性校验，不直写正文，改稿纪律不破）
3. 通道 C（补丁流）：编辑器产出 unified diff → `batch-edit.py` 应用（改稿套件既有链路，报数附收据）
4. doc/docx：只读（preview 元数据判定已有），编辑提示「转 md 走改稿套件」
5. 写入安全边界：**任何写路径不得越出项目根**；写入后提示重跑 `project-index diff` + `kit-compile --check`（看板内提示文案，不自动执行）

**交付物**：模板写功能 + serve 端点改造（或新端点）+ 鉴权说明 + 测试

**验收标准**：
- [ ] 通道 A：本地 Chrome 实测——打开看板 → 授权目录 → 编辑 md 保存 → 盘上文件变更且 diff 干净（只改目标文件）
- [ ] 通道 B：8431 端点实测读+写+鉴权拒绝三态；错误路径 no-store（缓存投毒教训红线）
- [ ] 通道 C：diff → batch-edit 应用 → repair-apply 记账全链通
- [ ] 越界写入被拒（`../` 逃逸用例）
- [ ] storyharness 测试全绿（panel-files 系改造后）；三 lint 0 error

**估算**：2–3 天 ｜ **风险**：FS API 仅 Chromium 系（可接受，文档写明）；写通道与「kit 只读数据」立场的边界要在 docs 里写死（写的是**用户产物**，不是 kit 知识面——知识面编辑走知识表格区的 diff 通道）
