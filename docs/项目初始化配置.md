# 项目初始化配置（项目配置.json）

> 每个 flow 初始化时自动装载的项目实例配置层。目的：**开跑前把题材、需求、灵感、出品严肃性、风格、AB 决策定死**——flow 带着底气跑，避免跑到 S3 才发现方向没对齐。
> 契约：`contracts/project-config.schema.json` ｜ 决策背景：爽版/标准版双版本曾是单项目建议，不应固化为所有项目的默认——现在归位为项目级配置。

## 快速开始

```bash
npx tsx src/cli.ts flow_init --project p-xxx     # 生成配置模板
# 填写 projects/p-xxx/项目配置.json 后：
npx tsx src/cli.ts flow_run --flow topic-selection --project p-xxx
# 或显式指定配置文件（会被复制为项目配置.json）：
npx tsx src/cli.ts flow_run --flow topic-selection --project p-xxx --config ./my-config.json
```

不创建配置文件 = 行为与从前完全一致（flow 默认值生效）。

## 字段

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `项目` | 项目 id（必填，须与目录名一致） | 一致性校验 |
| `题材` | 自由文本 | 组合进 `direction` 输入（"题材；需求；灵感"） |
| `需求` | 自由文本 | 同上 |
| `灵感` | 自由文本 | 同上；情绪切入/结构参考写这里 |
| `严肃性` | 探索 / 标准 / **出品** | 出品定位。出品级建议：人工门（presets 覆写）+ 开 AB + 全量打磨 |
| `风格` | **爽**（情绪浓度优先）/ 标准（合理性优先） | 映射 `route=hot/calm` |
| `AB测试` | true / false（**默认 false**） | true → `route=dual`（双版本+监管基线件，S3 工作量约翻倍）；覆盖 `风格` |
| `市场预估` | 自由文本 | 你的市场判断笔记——随背景卡下发给每个子代理，作为选题/结构阶段的底气 |
| `presets` | 可选 `{S2:"manual",...}` | 按阶段覆写执行模式 |
| `阈值预算` | 可选 `{<旋钮>: number}` | **OS-02 阶段 C**：把引擎内常量抬成「出厂默认 + 项目可覆盖」。键名/区间白名单 = `core/src/budget.ts::DEFAULT_BUDGET`（19 个旋钮：上下文装载 / 章长与文风配额 / 优化器规则 / 成本系数）。**留空即出厂默认**（不必抄一遍）；未知键、非数、越界会出现在任务包的「阈值预算告警」区，**绝不静默丢弃** |

## 阈值预算的合成与可调面（OS-02 阶段 C）

```text
flow.policy.budget（flow 模板层）
  → 出厂 overlay（flows/<id>/overlay.default.json）
  → 项目配置.json 的「阈值预算」        ← 本文件（实例层，面板写入）
  → 项目 overlay 的 set-policy{budget}  ← 运行时调整层（对象值按 key 浅合并）
  → resolveBudget()  唯一一次派生 ⇒ registry/effective.json 的 budget 块 → 页面纯消费
```

- **面板语义**：输入框**留空 = 不表态**（用出厂默认，且不写进配置；占位符显示出厂值）；
  填值 = 只覆盖该键。每行显示「生效值 · 区间 · 消费方」，标题栏徽标区分「出厂 N / 本项目已改 / 模板或运行时已改」。
- **消费方**（改一个阈值会影响谁，面板逐键标注）：`assembler.ts`（上下文与知识装载）、
  `aesthetic.ts`（章长 / 集数 / 三处文风配额）、`optimize.ts`（R1–R4 规则阈值）、`metrics.ts::costOf`（成本口径）。
- **改了要重跑**：阈值参与运行期判断与任务包组装，改完需再 `flow_run`/`flow_effect` 一次才会体现在
  `registry/effective.json`（页面显示的是上次派生结果）。

## 合并优先级

```text
显式入参（CLI --route 等 / MCP 入参）
  > 项目配置.json
    > flow.json inputs 默认值

阈值预算另有独立一层（见上）：flow.policy.budget < 项目配置.json 的「阈值预算」< 项目 overlay 的 set-policy{budget}
```

派发链路：配置 →（内核映射）→ run 输入 + 背景卡「出品定位/市场预估/市场快照基线」→ 每个子代理的任务包。子代理从第一拍就知道这是出品级还是探索级、要不要跑双版本——**返工的根源是意图晚知道**。

## 与 flow 默认值的关系

flow.json 的 `route` 默认值不再承担「项目偏好」职责（结构安全值而已）；你针对单个项目给的建议（双版本对照、三遍打磨、热点扫描）全部属于本配置层。要不要把某个建议升级为 flow 默认，由 flow 作者显式决定并写进 changelog——而不是由默认值悄悄决定。

## 模板库（自存 / 从零新建 / 套用 / 删除）

同一个配置要**跨项目复用**，不必每次手抄。模板库由内核 `core/src/cfg-template.ts` 统一管理，四动词
（`list` / `save` / `apply` / `delete`），CLI、HTTP（`POST /api/verbs/cfg_template`）、MCP 三面同一实现。
页面的「项目配置模板库」区只是它的消费面。

### 三种来源（一个清单）

| 来源 | 位置 | 可删 | 说明 |
|---|---|---|---|
| `blank`「从零新建」 | **合成，不落盘** | ✗ | 只含必填 `项目`，其余全走 flow 默认。**故意不抄官方默认**——否则会把别的项目的偏好悄悄带进来 |
| `official` 官方示例 | `<仓库根>/demos/<flow>/项目配置.json` | ✗ | 随仓库发布的示例配置，只读 |
| `user` 自存模板 | `<数据根>/templates/项目配置/<flow>/<名>.json` | ✓ | **在项目之外** ⇒ 项目删了模板还在，可跨项目复用 |

> **两个根不是同一个根**：自存模板在**数据根**（`--root` 指向处），官方示例在**仓库根**。
> 把二者当一处，临时数据根下官方示例就会凭空消失。

### 用法

```bash
# 列出（按 flow 过滤；同时返回坏文件清单 skipped，不静默跳过）
miniflow cfg_template --action list --flow topic-selection

# 把某个项目的配置存为模板（名字 = 文件名，含路径分隔符会被拒；同名须显式 --overwrite）
miniflow cfg_template --action save --project p-xxx --name 我的现代都市

# 套用到另一个项目（会覆盖其 项目配置.json；`项目` 键自动改写成目标项目）
miniflow cfg_template --action apply --project p-yyy --name 我的现代都市
miniflow cfg_template --action apply --project p-yyy --name 从零新建   # 清成空白配置

# 跨 flow 套用：默认拒绝（输入面/阈值未必兼容），须显式确认
miniflow cfg_template --action apply --project p-yyy --name 我的现代都市 --force

# 删自存模板（官方示例与「从零新建」明确拒绝：它们不是盘上的用户文件）
miniflow cfg_template --action delete --name 我的现代都市
```

### 纪律

- **用户能改的错一律 4xx**：名字非法 / 模板不存在 / 跨 flow / 同名已存在 —— 报 `INVALID_INPUT(400)`、
  `NOT_FOUND(404)`、`CONFIG_EXISTS(409)`，**不许被当成「服务器内部错误」**。
- **套用前必过 `project-config` 契约校验**，坏配置既不能存成模板、也不能写进项目。
- **诚实失败不瞎猜**：模板名在多个 flow 下都存在时，报歧义并要求显式 `--flow`——绝不「取第一个」。
- **模板 ≠ 配置**：套用只写 `项目配置.json`；真正生效仍要走内核合成 →
  `flow_run` / `flow_effect` 后写进 `registry/effective.json`。
- 页面不自己扫模板目录（`root` vs `repoRoot` 只有内核分得清）：清单一律来自内核读模型
  `registry/config-templates.json`，live 时由 `/live` 的 `configTemplates` 切片（内核现扫）覆盖。
