# 历史归档

**这里是决策历史，不是现行约束。**

当前有效的规格只有一份：[`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 判定规则

| 文档在描述 | 去哪 |
| --- | --- |
| 「现在是什么」 | `docs/ARCHITECTURE.md`（唯一事实源） |
| 「当初为什么」 | 本目录（只读） |

## 归档内容

| 类别 | 文件 | 说明 |
| --- | --- | --- |
| 版本宣告 | `版本宣告-*` | 各版本的破坏性变更决策。v5.0.0 执行模型已并入 ARCHITECTURE §6 |
| 规范系列 | `规范-*` | R3–R8/v6 各期设计规范。结论已按 ARCHITECTURE §7.3 迁移表并入 |
| 工单 | `工单-*` | 过程工单，记录任务分解与验收 |
| 交接回执 | `交接回执-*` | 阶段交接记录，含测试与验收数字 |
| 调研/设计 | `调研-*` `设计*` | spike 与探索稿，含被否决的方案 |
| 底座规格 | `底座规格-miniflow-harness.md` | 已被 ARCHITECTURE §1/§2 取代 |
| 验收回执 | `验收回执-*` | 阶段验收记录 |

## 阅读原则

1. **不要把本目录的内容当作现行约束** —— 它们记录的是当时的状态，可能已过时。
2. **遇到「当初为什么这么定」时，这里比空白更有用** —— 归档保留了决策路径，包括被否决的方案及其否决理由。
3. **发现与 ARCHITECTURE.md 冲突** —— 以 `contracts/*.schema.json` 和代码为准。
