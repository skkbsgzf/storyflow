## 四、行为变更（一处，其余等价换管道）

**未注册平台适配器就取用缺省 = 抛错点名**，不再静默回落任何实现。
这是本轮唯一的对外可见变化，且**已实测抓到一例外溢**：`storyharness/test/kit-wiring.test.ts` 首跑报
「FS 抽象层未注册平台适配器…须先 registerAdapters({ fs, path, proc })」（栈顶 `core/src/abstraction/defaults.ts`），
补一行 side-effect import（storyharness 是 Node 宿主）后 3/3 → 94/94。除此之外 core 侧调用点、落盘字节、
错误语义均未改——`nodeFs`/`nodePath`/`nodeProc` 三个名字保留（改名要动 166 处尾参而语义不换），
含义变更由 FS1 §四第 1/2 条与 §4.1 承载。

顺带两条口径纠正（不是本轮新发现的，但对本轮的门禁有效性是前提）：
① 工单 R7 卡面那条「core 包在无 `@types/node` 下 tsc 通过」**跑起来是空转的**（fastify／MCP SDK 的 d.ts 带
`/// <reference types="node" />`，`types: []` 拦不住传递性进场），R7 能落地的门是「import 普查双向死表」＋「依赖出包」；
② 普查正则**不能按裸文本**匹配：`defaults.ts` 里那句指路的错误消息必然写着该 import 哪一件适配器，
按裸文本会把自家消息判成违规（本轮自测就被绊过一次，已在测试注释里留痕）。
