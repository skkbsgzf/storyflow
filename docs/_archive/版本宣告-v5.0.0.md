# 版本宣告 · miniflow harness v5.0.0（agent-only 执行模型 + 断言 90 条去向总表）

> 生效：2026-09-21 ｜ tag：`v5.0.0` ｜ 事实源：仓库根 `VERSION` + `CHANGELOG.md`
> 拍板记录（用户指令原文）：「**确认不用的全部干掉，疑似有用的喂给 orchestrator 当做语料，未来我只用 agent，不用断言。**」
> 工单总纲：`docs/v5.0工单-断言体系退役与规则语料化.md`。本文档是宣告本体：退役对象与依据、新执行模型、即刻生效规则、90 条去向总表（= 工单 §二 正式版）、处决清单、批序验收。

## 一 · 为什么是 5.0.0

flow@3 / module@1 / decision@1 契约代数都没变——变的是**执行判决模型**：提交链上不再存在任何声明式断言闸，agent 成为唯一语义裁决者，机器只出证据。这是用户可见行为的破坏性变更（同样的产物，过去可能被断言打回，现在不会），semver 主档升 5.0.0。

盘账依据（工单 §〇，批0 实查）：台账 90 条，全库 20 个项目 journal 历史战绩中**真正打回过东西的只有 2 个 id**（AE-REPORT-DENSITY×5、AE-WNF-HOOK×2，共 7 次）；25 条以「无机器校验器，归评审/红方剖面」名义空转，累计 170 次 warn，而红方执行体从未存在。结论：机制空转、声明通胀。与红蓝对抗清理合并为一次退役。

## 二 · 新执行模型（agent-only）

```
规则语料(knowledge/rules/ ← C轨50条语义规则 + 用户导入)
        │ orchestrator 按 选题报告+剧本+前文 参数化激活（R8 决策记账：by+evidence+未激活回显）
        ▼
agent 写作/评审（唯一语义裁决者；文学判断=强模型档纪律保留）
        │ 评分证据 ← 确定性扫描器（T轨27条：scan_quality 内建步 / tools/quality-scan.py，收据制）
        ▼
端尾交付验收（gate_role:"kit-boundary"，人裁语义不变）
不达标 → reject 带证据（含扫描器 findings）→ 增补循环 → 2 轮仍不过 → blocked 问人
```

- **submit 路径上不存在任何断言闸**：`flow_submit` 只跑确定性完整性（存在性/空文/残渣/计数一致/artifact@1 头部/词汇表守卫）。
- 扫描器输出只是**证据**（数字、位置、密度），不是判决；证据里的 block 标签不拦截、不裁决。
- **铁律 10 升级**：一切「已扫描/已校验/质量报数」必须引用扫描器收据文件（`内部/质量扫描-*.json` 或 quality-scan 输出），禁止心算，无收据=删声明。
- 不变的边界：模型档位纪律、人工裁决只在 kit 边界（铁律 6）、K1 标尺装载单点与 9000 字封顶、R8 选择必须有事实、iterate seal 语义。

## 四 · 即刻生效的规则

1. **flow.json / module.json / overlay 里出现 `asserts` / `add_asserts` / `remove_asserts` = lint error**（flow-lint `E-ASSERTS-RETIRED`、module-lint `E-ASSERTS-RETIRED`、kit-lint `E11`），不再只是不推荐。要加质量条款：语义的进 `knowledge/rules/` 卡，可数的进扫描器（`core/src/aesthetic.ts` 或 prose-scan 族），**不加门、不声明**。
2. 提交链打回只可能来自完整性（残渣/空文/计数/头部/跨项目专名）；质量不达标走「评审 reject 带证据 → 增补循环 → blocked 问人」，端尾 kit-boundary 人裁收口。
3. `unverified` 态作废：没跑过的东西不再需要「登记没人验」——机器验不了的一开始就不该有机器条款，归语料卡让 agent 判。
4. 面板只读 `io.acceptance{scans,rules}` 与 `scan_quality` 收据；历史项目数据（v5.0 前 registry）只在页面生成器单点归一并显式标 `legacy`，**禁止面板侧双名兜底**（R4 §5.3）。
5. 报数必附收据（铁律 10 升级，见 §二）；`scan_quality` 空扫描 = 接线问题，journal 显式留痕，不算质量通过。
6. 规则卡由 `tools/rules-init.py` 自归档台账生成，此后**以卡为真相手工维护**（重跑生成器会覆盖改卡——批C 后禁止全量重跑）；卡进 `op.knowledge` 候选仍受 K1 装载与 R8 激活收窄约束，未装载候选必须回显。
