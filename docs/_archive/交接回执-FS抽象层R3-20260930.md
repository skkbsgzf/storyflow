## 二、本轮改了什么（口径）

1. **注入位**：`KernelOptions` 增 `fs? / path? / proc?`，`Kernel` 上 `readonly fs/path/proc`（缺省 = Node 适配器，宿主路径行为不变）。
2. **语义件收编**：新增 `core/src/abstraction/jsonio.ts`（`readJson / writeJsonAtomic / appendJsonl / readJsonl / LockDir`）；
   **退役删除 `core/src/fsio.ts`**（`git rm`，无 import 者）。
3. **写集 = P0 + P1 + P2 共 33 个源文件**（工单原排 R3 只做 P0 18 个）。理由与后果写在规范 §3.2：
   P1/P2 被 P0 直接调用，只迁 P0 会让被调方继续吃宿主盘，且「半抽象」违反 §四 第 3 条。**R6 因此只剩 P3 那 9 个文件**。
4. **台账 io 束化**（§四 第 6 条，本轮唯一的签名级 breaking 变更）：写路径函数改必传首参 `io: FsIo`，
   `src` 内 **104 处调用**全量透传——`journalAppend/journalQuery` 58、`recordDiag/readDiags/summarizeDiags/diagPath` 27、
   `readMetrics/recordMetric/metricsPath` 8、`setDecision/listDecisions/decisionsMap/decisionsDir` 11，外加 `syncIntentDecisions`。
   `Kernel` 结构上即满足 `FsIo`，所以调用点长这样：`journalAppend(kernel, projectDir, …)`。
5. **`runAsync` 进 v1**：`minitools.ts` 脚本壳本就是 `promisify(execFile)`（60s + SIGTERM），同步化会冻住 HTTP/MCP 宿主；
   `ProcResult` 的 `signal`/`timedOut` 与「退非零」分开建模。
6. **规范同步**：`docs/规范-FS抽象层-FS1.md` §2.2 / §3.1 / §3.2 / §3.3（新增 6 行语义对表）/ §四（第 6、7 条）/ **新增 §六 偏离清单 D1–D8**。

## 三、内存盘冒烟（`core/test/abstraction-smoke.test.ts`，4 用例）

三条断言各挡一类说谎：

1. `flow_run` 派发的任务包来自内存语料（`instruction.skill` / `outputContract.file` 命中）；
2. `flow_submit` 后产物 + `registry/artifacts.json` + `journal.jsonl` + `registry/metrics.jsonl` **只在内存盘**，
   且宿主盘上 `/mock-data-root` 与 `<HOST>/projects/p-fs1-smoke` **都不存在**；假进程 `proc.calls` 为空（agent 步没起子进程）；
3. 跑完语料逐字节不变（只读承诺）；
4. **改内存里的技能卡 → 任务包正文跟着变**——这条专治「宿主盘同内容时静默读宿主盘」，前三条抓不到它。

播种口径要说清：内存树的根字符串 = 宿主安装位置（`schema.ts::ROOT` 仍是宿主字符串，规范 §六 D3）。
所以本轮证明的是「**读写管道**已与宿主解耦」，不是「**语料寻址**已与宿主解耦」——后者要等 R7 拆包。
