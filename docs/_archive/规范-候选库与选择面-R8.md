# 规范 · 候选库与选择面（R8）

> **定则**：配置文件与 `flow` 是**候选库**，不是**约束**。
> 候选库说「有哪些」，决策说「选哪个」；**候选没有默认生效权**。
>
> 本规范治的是 R7 与 OS-02 之后暴露的第二类病：R7/OS-02 把散落的**值**收进旋钮表（`budget.ts` / `kit.op.config`），
> 但**选择**（题材/文风/结构/路线）一直被当成**值**在管——于是"引擎替作者拍板"换了个地方复发。

---

## 零 · 判据：选择 vs 值

**一句话判据**：

> 这个字段的合理取值空间是**有限枚举且互斥**吗？
> 是 → **选择**（不许有 `default`，必须有决策事实）
> 否 → **值**（该有 `default`，适用 `resolveBudget` / `resolveToolConfig` 那套）

| | 归属 | 例 | 现状对错 |
|---|---|---|---|
| 选择 | 本规范（选择面） | `route`（hot/calm/dual）、文风、结构母型、题材过滤标签 | ❌ 全都被当成了值 |
| 值 | R7/OS-02 已治 | `contextBudget`、`chapterBlockChars`、`timeoutMs`、`maxChars` | ✅ 保留不动 |

**实测反例（本仓现状）**：

- 9 条 flow 的 `inputs` 共 32 项，其中 **`type=enum` 6 项，6/6 全带 `default`**（100%）。
- 已发生的代价写在 `core/src/project-config.ts` 的 D2 注释里：`项目配置.json` 写了 `route=dual`，
  `state.inputs.route` 却落到别的档 ⇒ `when:{input:route,eq:"dual"}` 的**双版本支线两条都没激活**。
  这不是配置写错，是**给一个"选择"配了默认值**——默认值一旦生效，选择就静默消失了。

## 一 · 三件东西

### 1.1 候选库 `catalog`（供给面）

**位置（两个根，必须分开）**：

| 层 | 根 | 路径 | 谁写 |
|---|---|---|---|
| 出厂 | 仓库根 `repoRoot` | `kits/`、`knowledge/`、`skills/`、`flows/`、`demos/` | 仓库维护者 |
| 用户本地 | 数据根 `dataRoot` | `<dataRoot>/catalog/<kind>/` | 用户随时增删 |

> 两个根合成一处 = 临时 `--root` 下出厂候选凭空消失 —— OS-04 余量（`cfg-template.ts`）已踩过一次。

**条目字段**：

```jsonc
{
  "id": "style/zhang_ailing",      // 全局唯一
  "kind": "style",                  // 池名：style / structure / trope / route / skill …
  "tags": ["年代", "言情", "冷感", "克制"],   // ← 过滤轴（唯一）
  "applies_when": "民国/都市苍凉题材、叙述者克制",  // 人读的适用条件，不参与求值
  "desc": "张爱玲式冷感明喻、物象记忆触发、零对话",
  "file": "skills/ghostwrite.md"     // 或 references/ 目录
}
```

**关键：catalog 条目没有 `default` 字段。** 候选不参与默认值语义（见铁律 2）。

**现状种子（不是从零开始）**：
`knowledge/index.json` 已有 `routes` / `dimension` 两条标签轴，但——

- 86 条里**只有 3 条**带可用路由标签：`kb/aesthetic/style-routes`（`hot,calm`）、
  `kb/formats/webnovel-fastfood`（`long-form`）、`kb/structure/episodic-webnovel`（`long-form`）；
  其余 42 条是 `["all"]`、41 条**根本没有 `routes` 键**。
- `applies_to` 在源 md frontmatter 里**有**（如 `kb/structure/catalog` 写 `["short-drama","comic-drama","long-form"]`），
  但 `tools/distill-kakaxing.mjs` 生成 index 时**整个字段被丢掉**——索引里 `applies_to` 出现 **0 次**。
- `core/src` 里 `routes` 的消费者：**0 处**。

⇒ 过滤轴**不是缺机制，是缺标签 + 索引丢字段**。

### 1.2 决策事实 `decision`（选择面）

落到 `<项目>/decisions/<key>.json`：

```jsonc
{
  "format": "decision@1",
  "key": "genre",                       // 与 catalog.kind 的过滤关系由 decl 声明
  "by": "analysis",                     // ← 谁做的决策（节点 id / 人）
  "at": "2026-09-20T22:41:03+08:00",
  "picked": ["年代言情"],
  "excluded_tags": ["悬疑", "玄幻"],     // 反向声明（可选）
  "evidence": "选题定位.md#§2 类型判定", // ← 依据哪份产物
  "confidence": 0.8
}
```

**硬要求**：

- `by` 与 `evidence` **必填**。无来源的决策 = 猜，进 `issues` 不进 `values`。
- 可校验：`picked` / `excluded_tags` 里出现的标签，**必须能在 `catalog[kind]` 的 `tags` 并集里找到**；
  找不到 → `issues` 项（"决策引用了不存在的标签"），不静默。
- 落盘者：`set_decision` 动词（内核）；产出者：agent 节点交卷时结构化声明（不靠自由文本抽取）。

> 为什么必须有独立文件而不是塞进 `flow.inputs`：`resolveInputs` 只在 `flow_run` 时算一次，
> 之后 `state.inputs` **冻结**，产出它的上游节点还没跑。决策是**运行中产生的事实**，
> 与"开跑前的输入"是两种东西，不能共用一个容器。

### 1.3 选择面 `resolveSelection`（求交面）

```ts
export interface SelectionResult {
  loaded: CatalogItem[];
  /** ← 本仓缺的那一格：因与本次决策不符而**主动不选**（不是缺失、不是优化器剔除） */
  excluded: Array<{ id: string; decisionKey: string; reason: string }>;
  /** 声明了却不存在 / 标签引用不存在 / 缺决策 */
  issues: string[];
  /** 本次实际参与求值的决策（供面板回显"凭什么这么选"） */
  decisions: Record<string, Decision>;
}

export function resolveSelection(input: {
  catalog: CatalogItem[];          // 已按 kind 分组
  decisions: Record<string, Decision>;
  decl: { pool: string; where?: { tags?: string[]; notTags?: string[] }; onMissingDecision?: "block" | "load-all-with-warning" };
}): SelectionResult;
```

**与 `resolveBudget` 同构**（纯函数、无 IO、返回 `{values, sources, issues}` 形状）——这是本仓已验证可靠的形状，
不发明第二套。

**无决策时**：默认 `onMissingDecision: "block"` —— **显式失败**，不装作选了、也不全装。
要全装必须显式声明 `"load-all-with-warning"`，且任务包里会多一段 `## 本步未按决策过滤（全装）` 的告警。

## 二 · 接进现有的三个口

### 2.1 知识装载（`assembler.ts::loadKnowledge`）

**现在**：`loadKnowledge(root, ids, exclude, caps)` → `{cards, text, missing, excluded}`。
`ids` 是**点名清单 + glob**，`caps` 是**全装后截断**。任务包回显三段：
`## 标尺缺口`（声明了却不存在）、`## 已剔除条款`（优化器按指标剔除）、`## 禁词表`。

**缺的正是「因不相关而未选」**——现有三段都答不出"为什么没装悬疑梗卡"。

**改**：`ids` 升级为带 `where` 的池声明：

```jsonc
// kits/prose/kit.json 的某 op 里
"knowledge_pools": [
  { "pool": "kb/trope/*",      "where": { "notTags": ["$decision:genre.excluded_tags"] } },
  { "pool": "kb/aesthetic/*",  "where": { "tags": ["all", "$decision:genre.tags"] } }
]
```

- `$decision:<key>.<field>` 是**唯一**的决策引用语法（不新造 DSL）。
- `resolveKbPaths` 的 glob 展开点**保留**（唯一实现），过滤层加在它**之前**（先过滤 entries，再展开 file）。
- 任务包新增一段，与现有三段同构：

```
## 未装载的候选（与本次决策不符——不是缺失，是过滤）
- kb/trope/xuanhuan-rebirth（genre=年代言情，标签不匹配）
- kb/aesthetic/ai-trace? （×）
```

### 2.2 技能选择（`assembler.ts:305`）

**现在**：

```ts
const skillId = node.skill ?? opRef?.skill;   // ← 单值，写死在 flow 节点 / kit 上
```

选了文风 = 在 `flow.json` 里把一个字符串焊死。用户要的是「在多个文风 skill 中**选**，而不是配置」。

**改**：

```jsonc
// flow 节点 / kit op 侧声明的是"池"，不是"那一个"
{ "kit": "prose", "op": "draft", "skill_pool": "style/*" }
```

+ `decisions["style"].picked = ["zhang_ailing"]` → 选中 `skills/<对应文件>`。

- flow 里**写池**；写具体一个只在**没有决策机制时的降级逃生口**，且必须 lint 标 `warn`（"绕过了选择面"）。
- 无决策 + 未声明逃生口 → **显式报缺**，不回落。回落 = 引擎替作者挑文风 = 死约束。
- 现状：34 个 skill 平铺在 `skills/`，**无 `tags`、无池、无选择记录**（`structure-design.md` / `ghostwrite.md` 等全靠节点硬引）。

### 2.3 结构选型（`kb/structure/catalog`）

**现在**：`knowledge/structure/catalog.md` 里有 6 种结构母型（复仇/救猫咪/逆袭/双线交叉/倒钩回归/单元宿命），
frontmatter 是 `routes: ["all"]` + `applies_to: [3 值]`（且 `applies_to` 被索引丢掉）。
⇒ **目录全装**，agent 在脑内选完写在产物里，**下游读不到**。这是"选型目录已有、但选型这个动作
没有落成事实"的典型。

**改**：6 种母型各自成为带 `tags` 的 catalog 条目；`structure-design` 节点产出 `decision:structure`；
下游按它过滤（选了"复仇"就不必再装"救猫咪 15 节拍"的细节）。
这直接减少上下文体积，同时让"为什么选复仇"可回放。

## 三 · 铁律（拟并入 `AGENTS.md`）

1. **选择不许有 `default`。** `<flow>.inputs[type=enum]` 出现 `default` → `flow-lint` **error**。
   判据即「零 · 判据」。
2. **catalog 条目没有默认生效权。** 未被任何 decision 命中 = **不装载 + 显式回显**；不静默、不回落、不全装。
3. **决策必须有 `by` 与 `evidence`。** 缺则进 `issues`，不进 `values`。
4. **`excluded` 必须带理由。** 「为什么没装 X」是本仓第九次被咬的同一格
   （`kb.missing` / `cfg.unknownKeys` / `budget.issues` / `patchMisses` 全是它）。
5. **两个根。** catalog 出厂在 `repoRoot`、用户补充在 `dataRoot`，合成一处即错（OS-04 余量已踩）。
6. **决策是运行中事实，输入是开跑前事实。** 不许把决策写回 `flow.inputs`（`resolveInputs` 只跑一次，
   写回是伪造历史）；决策只在 `decisions/` 里生长。
7. **选择结果必须能在页面上回答三问**：选了哪个 / 凭什么（`by`+`evidence`）/ 排除了哪些及理由。
8. **调研能定的，不逼人开口。** 结论来自盘面证据的选择（如 `region`）声明 `required:false` = **可选先验**：
   缺席不抛也不兜底（不猜值），由调研步交卷时 `set_decision` 定案；先验若给了，内核单向落成
   `decision:<key>`（`by=user.preference`，见 `inputs.<k>.feeds_decision`）——反向（决策写回 inputs）仍禁止。
9. **选择声明了就得有人读。** enum 输入既无 `bind`、又不被 `modules[].when` 引用、也无 `feeds_decision`
   → `W-ENUM-DEAD` 点名。「选了没人读」与 `route=dual` 那次同源（断点清单 #1/#6 的合流形态）。

> **落地状态（2026-09-21，生产端首个消费者已接线）**：断点 #1/#2/#5 收口——`kb/trope/*` 13 张梗卡补市场轴
> 标签（CN 10 / NA 3），`modules/topic.find-trope` 的硬剔除名单（`exclude_knowledge` 剔 na-*）退役，改
> `knowledge_pools` + `$decision:region.picked` 过滤（未定案 = 两区全装 + `选择面告警`），`plot.novel-bible`
> / `world-forge` 同迁；`region` 降为可选先验（`feeds_decision: region`），`find-trope` 兼该决策的生产者
> （`skills/find-trope.md` 判定纪律 5）。仍开放：断点 #6（`CondContext` 读不到 decisions ⇒ 边/模块级
> `when(decision)`）、`route` 在 4 条 flow 里被 `W-ENUM-DEAD` 点名（批A 把 `when route==dual` 折进了 desc，
> 待模块级条件派发或 style-routes 卡拆分后接）。

## 四 · 断点实测清单（本规范要治的东西）

| # | 断点 | 证据 | 现状性质 |
|---|---|---|---|
| 1 | enum 输入全带 `default` | 9 flow / 32 inputs / 6 enum / **6 带 default** | 选择被当值 |
| 2 | 路由标签轴是死的 | 86 条知识，**仅 3 条**非 `all`；`core/src` 消费者 **0** | 声明零消费 |
| 3 | 索引丢字段 | 源 md 有 `applies_to`，index 里出现 **0 次** | 生产者写了、索引不搬运 |
| 4 | 技能单值焊死 | `assembler.ts:305` `node.skill ?? opRef.skill` | 无池、无选择 |
| 5 | 结构目录全装 | `kb/structure/catalog` `routes:["all"]`，6 母型一次性进上下文 | 选择不落事实 |
| 6 | 条件求值读不到产物 | `cond.ts::CondContext` = `inputs/lastRejectReason/gateVerdict/nodeVerdicts/pendingInstances`，**无 decisions** | 决策无下行通道 |
| 7 | 决策无落点 | 全仓无 `decision@` / `decisions/` / `set_decision` | 能力缺失 |

> 7 条同源：**"选择"这件事在本仓没有家**——没有容器（表）、没有产物（decision）、没有求值（resolveSelection）、
> 没有回显（excluded 带理由）。对照铁律⑥「能力必须有家：①声明 ②内核执行 ③UI 可见 ④lint 可校验」，四环全断。

## 五 · 不做（范围纪律）

- ❌ **不动 `resolveBudget` 那一族**：`contextBudget`/`chapterBlockChars`/`timeoutMs`/`maxChars` 是**值**，
  `default` 语义正确，保持现状。
- ❌ **不删 `flow.inputs`**：改名/定位为"选择面"，只去掉 `default`，不搬家。
- ❌ **不重写 `distill-kakaxing.mjs`**：只补 `tags` / `applies_to` 输出，不改蒸馏算法。
- ❌ **不新造 DSL**：决策引用只有 `$decision:<key>.<field>` 一种语法。
- ❌ **不把 catalog 做成数据库**：仍是文件 + 索引，沿用 `knowledge/index.json` 的形状。
