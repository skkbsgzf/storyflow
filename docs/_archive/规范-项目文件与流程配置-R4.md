> 状态：**生效**（配套 `contracts/artifact-header.schema.json`、`contracts/flow.schema.json`、`tools/artifact-lint.py`、`tools/flow-normalize.py`）
> 适用范围：`projects/` 下全部过程交付件；`flows/*/flow.json` 全部节点与边
> 日期：2026-09-17

## 零 · 这份规范解决什么

现状体检（`p-fq-001` + 7 个 flow）暴露四类问题，本规范逐条给出机器可判的约束：

| # | 问题 | 实证 |
| --- | --- | --- |
| 1 | **过程件无机器可读头部**，版本/上游/审核背景写在散文里 | `多视角意见书-R1.md` 首行写「验收对象：选题报告 v8 + 梗卡 v7 + 素材解剖 v7」；`registry/artifacts.json` 里这些是结构化字段，md 里是句子 |
| 2 | **版本靠文件名后缀**，且后缀有 6 种方言 | `-v6…-v12`（收据）、`-R1/S2/S3/终稿`（意见）、`-r1/r2`、`-v10-r1`（评审表） |
| 3 | **目录按前缀混装**，用途不可辨 | `内部/` 一个桶装了红方意见、83 KB 知识快照、7 份扫描收据、评审表、诊断单、对照表 |
| 4 | **同一概念多个字段名 + 条件不可求值** | 产物路径 `file`(36) / `output`(18)；知识 `kb` / `loads` / kit.op；边 `transform` 三命名空间（skill 36 / sm 40 / core 22）；3 条边 `when` 内核解析不了 → **永久死线** |

**第 4 条最致命**：`loop-r4-miniguided`、`loop-r5-first3`（`when:"rejected"`）与 `e-loop`（`when:"还有未写章"`）在 `cond.ts::evalWhen` 下返回 `{active:false, reason:"无法识别的 when 表达式"}`——**前端看得见、内核判不动的打回回注线**。同一个条件两套判定逻辑，是"线不可信"的根因。

## 一 · 目录分层：路径只回答「给谁看」，语义全部进头部

```
projects/<id>/
├── 项目配置.json          ① 唯一输入契约（改它 = 改需求；已冻结字段改动仅对重跑生效）
├── state.json             ② 内核真相（run 状态机，页面不回写）
├── journal.jsonl          ③ append-only 事件流
├── <输入材料>.md|.txt     ④ 根级 = 输入材料，仅限 kind:novel-txt（src 节点产物）
│                            例：选题素材.md / 参考作品.md / 需求.md / 分场卡.md
├── 世界书/                ⑤ 连续性事实库（canon truth，非产物）：人物/势力/设定/伏笔/编年
├── 内部/                  ⑥ 过程交付件（不对外）
│   ├── 意见/              　有裁决权的意见书：红方多视角、评审表
│   ├── 收据/              　零 token 的确定性工具输出（机器证据，每节点一份、覆盖式）
│   ├── 依据/              　装载进上下文的知识快照（外部输入物化，非本项目创作）
│   └── 稿本/              　本项目创作的中间稿本：梗卡、节拍卡、层稿、框架案、大纲
├── 对外交付/              ⑦ 唯一交付出口，`NN-` 前缀定序（01/02/03/04）
├── 章节正文/              ⑧ iterate 实例槽位（逐章成文）
├── registry/ snapshots/   ⑨ 机器目录（页面文件架不展示）
└── workflow.html          ⑩ 生成页（唯一 HTML 承载）
```

**准入规则（可机器校验，`artifact-lint` 逐条执行）**

| 目录 | 谁可以进 | 谁禁止进 |
| --- | --- | --- |
| 根级 | `kind:novel-txt` 节点产物、三个元数据文件 | 任何 agent/core 产物 |
| `世界书/` | 人物/势力/设定/伏笔/地理/底牌/编年 七类事实条目 | 意见、收据、稿本 |
| `内部/意见/` | 由 gate 或 review 类 op 产出的意见书 | 稿本、收据 |
| `内部/收据/` | `check_*` / `continuity_*` / `*-scan` 等确定性工具输出 | 任何 LLM 产物 |
| `内部/依据/` | `kb_load` 物化的知识快照 | 本项目创作内容 |
| `内部/稿本/` | LLM 创作的中间件（层稿/节拍卡/框架案/大纲） | 收据、依据快照 |
| `对外交付/` | 甲方可见成件（md/docx/html），**必须 `NN-` 定序** | 过程件 |

> 关键取舍：**不再按"阶段/前缀"分目录**。阶段信息在 flow 里，产物类别在头部 `class` 字段里，路径只表达受众边界。目录从 6 种前缀收敛为 4 个语义桶。

## 一、目标读者

正文……

**规则**

1. **头部是唯一版本与审核真相**。正文**不得**再复述轮次、上游清单、审核背景（"本轮""第 N 版""v8""验收对象：…v7"一律违规——进头部）。
2. **正文前只允许两行**：`# 标题` + 一行 `> 摘要（≤60 字，说结论）`。摘要后必须空行。
3. `id` 取 `kit.op`；不属任何 kit 的写 `core.<minitool>`；世界书条写 `world.<类>.<名>`；输入材料写 `input.<名>`。
4. `upstream` 由内核在提交时按 `registry.artifacts[].inputs` 自动回填，**不要求人写**；人写则必须与注册表一致（lint 校验）。

## 三 · 命名与版本规则

**一条铁律：文件名不承载轮次。**

| 违规形态 | 实例 | 规范形态 |
| --- | --- | --- |
| `-v<N>` | `prose-scan-v12.md` | `内部/收据/prose-scan-gate-final.md`（覆盖式，历轮在 `snapshots/`） |
| `<对象>-v<N>-r<N>` | `评审表-终稿-v10-r1.md` | `内部/意见/评审表-终稿.md`，`round:1` + `reviews: 终稿@v10` 进头部 |
| 无节点判别的同名多件 | 六个门都产 `多视角意见书` | `内部/意见/多视角意见书-<节点id>.md`（如 `-gate-r1`、`-red-s2`） |

- **同名多件**用 `-<节点id>` 后缀判别（节点是稳定标识，轮次不是）。
- **收据类覆盖式**：一个节点一份，每轮覆写；历轮证据由 `snapshots/<node>/r<N>/` 与 local history 承担。
- **交付件定序**：`对外交付/NN-<名>.<ext>`，`NN` 与 `flow.outputs[].order` 对齐（01 选题 / 02 终稿 / 03 小纲 / 04 成稿）。
- `artifact-lint` 禁用正则：`v\d+`、`第\d+版`、`_?\d{1,2}版`；`-R\d`/`-r\d` 仅在作为已有节点判别时允许。

## 四 · 污染禁令（正文）

`artifact-lint` 与内核 `artifact-header` 校验**同时**扫描，命中即 block：

| 类别 | 禁止 | 落点 |
| --- | --- | --- |
| 会话口吻 | 以 `思考 / 分析过程 / 让我 / 我先 / 用户说 / 用户要求 / 我需要 / 首先我 / 接下来我 / 按照要求` 开头的段落 | 删除 |
| 工具残留 | heredoc 结束符、`cat >`、`wc -l`、`<<'EOF'` | 删除（已有 `no-debris`） |
| 长日志 | 连续 >3 行的原始工具输出 | 移入 `内部/收据/` |
| 版本叙述 | `本轮 / 第N版 / v\d / 上一版对比` 出现在正文首屏 | 移入头部 |

**允许**（不属于污染）：正文内的业务判断句、评审结论、技法引用；故事内部以"思维链"为设定名词者按普通词处理。

## 五 · flow 配置项统一（flow@2）

### 5.1 字段名唯一化

| 概念 | 现行（多套） | **统一为** | 处理 |
| --- | --- | --- | --- |
| 产物路径 | `file`(36) / `output`(18) | `output` | `file` 兼容读、标记 deprecated、lint warn |
| 知识依据 | `kb` / `loads` / `skill.bind.knowledge` | `kit` + `op`（唯一事实源 = `kits/*/kit.json`） | 已迁移；`kb`/`loads` 仅 core 节点保留 `loads` |
| 校验声明 | `check`(core) / `review`(agent,gate) / `asserts` | `asserts: string[]` | 全部归一 |
| 执行体 | `skill` / `minitool` / `transform` | 节点：`kit`+`op`；边：派生或 `via` | `skill` 保留兼容位 |
| 阶段 | 节点 `stage` 自由值 | 必须 ∈ 顶层 `stages[].id` | lint 校验 |
| 边条件 | `when` 自然语言 | `when` 结构化对象（见 5.2） | 全部归一 |
| 边角色 | `optional` / `loop` 布尔 | `role: flow\|reject\|optional\|loop\|batch` | 归一 |
| 边执行语义 | `transform` 三命名空间 | **派生**；不同才写 `via: "<kit>.<op>"` | 删冗余声明 |

**为什么边的 `transform` 该删**：98 条边里 98 条都在描述「目标节点做什么」，而目标节点自己已经用 `kit`+`op` 说清了。实测「`via` = 目标节点执行体」这条派生规则可还原全部 98 条既有语义，所以这 98 处声明是**纯粹的漂移面**——删掉它，不一致在结构上不可能发生。

### 5.2 边参数化（可视化 + 可求值）

```jsonc
{
  "id": "e-r1-back",
  "from": "gate-r1",
  "to": "tropes",
  "role": "reject",                          // flow | reject | optional | loop | batch
  "when": { "verdict": "send-back",          // 结构化谓词，与 cond.ts::evalWhen 同源
            "cause": "梗选型" },
  "params": { "scope": "本阶段",              // 面板可渲染的参数
              "mode": "定点重做" },
  "desc": "R1 根因=梗选型 → 回找梗师重做"
}
```

**`when` 谓词语法**（缺省 = `true`，无条件）

| 形态 | 语义 | 求值依据 |
| --- | --- | --- |
| `{ "verdict": "send-back" }` | 门裁决为打回 | `state.gate.verdict` |
| `{ "verdict": "pass-with-conditions" }` | 带条件通过 | 同上 |
| `{ "challenge": true }` | 存在挑战票 | 门节点 verdict |
| `{ "cause": "梗选型" }` | 根因指认 | `state.lastRejectReason` |
| `{ "input": "route", "eq": "dual" }` | 输入取值等于 | `state.inputs[key]` |
| `{ "input": "批注回流", "eq": "on" }` | 同上（布尔取 `on`） | 同上 |
| `{ "input": "pendingChapters", "gt": 0 }` | 数值比较 | 同上 |
| `{ "loop": "pending" }` | 回边：还有未完成实例 | 运行时就绪批 |
| `{ "any": [ … ] }` / `{ "all": [ … ] }` | 组合 | 递归 |

**兼容**：`when` 仍可为字符串（按旧 `evalWhen` 解析），但 lint 报 `warn`；**不可解析的字符串 = block**（现行 3 条边属此列）。

### 5.3 前端面板渲染契约

统一「**1 节点 = 4 页 + 1 条**」，字段全部由 `contracts/flow.schema.json` 白名单驱动，未登记字段**显式标「未规范化」**而非静默丢弃（现行 `nodeInfoPaper` 读 `m.kb`，而迁移后 `kb` 已删 → 面板静默空白，属于静默丢字段事故）。

| 面板 | 数据源 | 现行问题 |
| --- | --- | --- |
| 产物页 | `output`（唯一）+ `snapshots[node]` 历轮 | `nodeOutputs()` 用 `["output","file"]` 双名兜底 |
| 参数页 | `kit/op/asserts/iterate/spotCheck/webSearch/policy/route` | 只渲染 `skill/minitool/kb`，kit/op 不可见 |
| 依据页 | kit.json 解析出的知识卡 + `内部/依据/` 快照 | `m.kb` 已删，显示为空 |

| 连线 | `role/when/params/via?` | `isEdgeActive()` 硬编码 `"rejected"`、`RS.nodes["gate-r2"]` 字符串嗅探 |

> **已落地（2026-09-17）**：页面内置与 `core/src/cond.ts` 同源的求值层（`evalWhen` / `whenText` / `edgeRole` / `isBackEdge` / `edgeVia` / `condCtx`），`isEdgeActive()` 已删除；边面板渲染 `role` / 结构化条件（含当前成立与否）/ `params` / 派生 `via`；节点面板渲染 `kit.op`（由 `DATA.kits` 取知识依据与校验）+ `loads/webSearch/spotCheck/policy/route/filterBy/reviewers/gate_role/oversight/iterate/when/onFail`，未进白名单的字段显式标「未规范化」；审核页读产物 `artifact@1` 头部 `review`（无头部时明确说明「以意见簿为准」，不留白）；交付页新增「交付清单核对」（`flow.outputs` 为唯一事实源，磁盘上无主的交付件显式告警）。回归门禁 `tools/page-lint.mjs`。
