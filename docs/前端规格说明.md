# StoryFlow 工作台 · 前端规格说明

> 版本：v1.1（对应流程引擎 flow@3 · 模块化编排）
> 读者：使用本工作台进行小说 / 短剧创作的作者、编辑与评审人员。
> 本说明书描述你在浏览器里看到的每一个界面：它能做什么、你在哪里看什么、动哪里会发生什么。

---

## 一、这是什么

StoryFlow 工作台是一个**创作流水线的可视化工作台**。它把一次创作（一部长篇小说、一部短剧）组织成一条**流水线**：

```
灵感 ──▶ [选题模块] ──◇──▶ [编剧模块] ──◇──▶ [写作模块] ──◇──▶ [交付模块] ──▶ 成品文档
              选题报告        ◇剧本           ◇正文终稿           docx
```

- 每个方框是一个**模块**（一种工种：选题、编剧、写作、交付），它吃一份输入，交一份成熟产出；
- 方框之间的 ◇ 是**连接件**（模块交接的检查站）；
- 你在浏览器左侧看到这条流水线的画布，右侧是这条流水线产出的**所有文档**——每份文档都可以直接在页面上阅读、编辑、保存。

一句话：**左边是流程怎么走，右边是走出来的字。**

## 二、十个核心概念（读对话不迷路）

| # | 概念 | 人话解释 |
|---|---|---|
| 1 | **项目** | 一次具体的创作任务（如"曹操穿越武大郎"）。一个项目绑一条流程。 |
| 2 | **流程** | 模块的排列顺序与配置，例如：选题 → 编剧 → 写作 → 交付。同一个流程可以服务多个项目。 |
| 3 | **模块** | 一种工种的完整工具箱，有明确的**职责三件套**：输入职责（吃什么）、输出职责（交什么，一份成熟交付件）、验收职责（机器检查什么）。画布上每个色块是一个模块实例。 |
| 4 | **节点** | 模块里的一个工位。三种执行体：**智能体**（AI 写，消耗 token）、**确定性工具**（程序直出，零 token）、**脚本**（外部程序，如导出 Word，零 token）。 |
| 5 | **连接件** | 模块与模块之间的检查站，两种模式：**auto**（自动放行，灰色虚线）/**manual**（人工放行，金色实线）。manual 的检查站由你决定放行或驳回——**驳回意味着整个上游模块重跑**，不是单节点重做。 |
| 6 | **交付件 vs 过程件** | 每个模块只交**一份成熟交付件**（如《选题报告》《剧本》《终稿 docx》）；工作过程中的草稿是**过程件**，默认折叠收在"模块内幕"里，不打扰你。 |
| 7 | **验收三态** | 每个节点声明的机器检查项，状态只有三种：**pass**（过）/ **warn**（黄，提示）/ **block**（打回重做）；机器查不了的检查项明确标 **unverified**，不假装通过。 |
| 8 | **命中率徽章** | 衡量"注入给 AI 的写作标准，有多少真的被用进了产物"——绿色高、红色低，一眼看出哪一步在空转。 |
| 9 | **效率徽章** | 衡量一个工位"被下游真正使用的次数 ÷ 它的成本"——长期没人用它的产出，优化流程时会提案裁掉。 |
| 10 | **负反馈** | 每个模块跑完，你拿到一份**模块结果报告**（产了什么、验收过没过、指标如何），你可以在产物上**批注**；批注会流入**提案池**，由优化 agent 拆解成"调参数 / 调顺序 / 改流程 / 改提示词"的改稿提案——**提案永远先等你拍板，不会自动生效**。用得越久，流程越顺手。 |

## 三、界面导览

### 3.1 顶栏（最上面一行）

| 按钮 | 干什么 |
|---|---|
| 项目切换器 | 左上角下拉框，切换当前打开的项目（可多开页签对比）。 |
| ⇪ 导入新流 | 打开**流商店**，浏览全部可用流程，一键导入到当前项目。 |
| 📦 产物管理 | 打开**交付物清单**：模块交付件（含 Word 文档下载）、逐章文档槽位、旧目录交付，以及"交付清单核对"（流程声明要交的 vs 磁盘上真交了的，逐件对账）。 |
| ▦ 中间件 | 打开**设定真相库（世界书）**：人物、势力、地理、伏笔、底牌等设定档案。只有流程真的产出了世界书，这个入口才可用；没有时按钮会注明设定在哪个过程件里。 |
| ▤ 文档架 | 打开右侧**项目文档架**（详见 3.4）。 |
| ⚙ 设置 | 字号缩放等显示偏好。 |

### 3.2 画布（左侧大区域）

- **模块色块横向拼接**：从左到右就是执行顺序，色块顶栏写「01 · 选题 · 能力 2/2」这样的编号与能力启用情况。
- 色块内部：**竖向**排列该模块的工位（节点）；模块与模块之间用**连接件**横向缝合，连接件上标注放行模式（自动 / 人工）与当前状态。
- **节点卡片**：标题 + 小字副题（用的哪个技能/工具/脚本），左上角圆点表示状态（绿=完成、黄=待决、灰=未启动），右上角徽章是该工位的效率与命中采样。
- **点任何一个节点**，右侧打开它的**节点页**（见 3.3）。
- 顶部有 **⊞ 本轮 / ▸ 下一轮** 按钮：一键把画布适配到当前进行中的模块。

### 3.3 节点页（右侧，点节点后）

从上到下依次是：

1. **模块结果报告**（若所属模块已收口）：本模块交了什么、验收三态一览、提交/重试/命中/耗时指标——这是你看"这一段做得怎么样"的第一入口。
2. **职责三件套**：该模块的输入职责 / 输出职责 / 验收职责（设计之初就声明的契约）。
3. **产物文档**：本节点的产出全文，**直接编辑**，工具条提供：保存改动、撤销/重做、**⏱ 历史**（自动留档的历次版本，可对比回滚）、**重跑**（标记后由流程引擎重新执行本节点，未变化的上游走缓存）。
4. **节点说明**：能力（kit.op）、执行体（技能/工具/脚本）、知识依据（本步参考了哪些写作标准）、校验（机器检查项）、产物路径、状态与轮次。
5. **批注 · 审核意见**：本节点的全部批注 + 输入框。批注会汇入"审核意见簿"，可导出 .md 回传——这就是负反馈的入口。

验收门类节点（连接件/边界门）会额外出现**裁决条**：通过 / 驳回（含根因选择或模块回退语义）。

### 3.4 文档架（右侧默认页）

从上到下：

- 封面（项目名 / 流程版本 / 更新日期）
- **中间件 · 设定真相库** 与 **审核意见簿** 两张常驻卡（世界书卡只在流程真的产出世界书时出现）
- **交付件**：每模块一份的成熟交付，Word 文档点「下载/打开」
- **模块过程件**：按模块折叠（点开才展开），不打扰视线
- **内部产物 / 旧目录交付**：存量内容，显式标注

### 3.5 产物管理（📦 打开）

- **模块交付**：每模块的唯一成熟交付件，docx 等格式直接下载；
- **章节文档**：逐章写作的流程会显示每章槽位（已完成可打开，未完成不显示虚位）；
- **交付清单核对**：流程声明要交的每一件，磁盘上有没有、对应哪个节点，逐件 ✓/… 对账；没被任何声明认领的文件会显式告警。

### 3.6 其他面板

- **世界书（中间件）**：类型化设定网格 + 搜索，按类型/标签过滤；设定条目即文件，改完即存。
- **审核意见簿**：全部验收门的裁决记录 + 所有批注，一键导出 .md——可回传给生产方合并进下一轮。
- **流商店**：全部可用流程的卡片（模块数 / 节点数 / 技能 / 使用情况与版本对比），一键导入。
- **编排面板（生成式编排）**：给关心流程本身的人看——当前策略（连接件放行模式 / 自动调优）、编排指纹、项目覆盖补丁数、优化提案待批数、指标事件数、裁决分布。

## 四、常见任务 How-to

### 跑一个新项目
流商店选一条流程 → 导入 → 按 `flow_run` 启动（输入题材方向等参数）→ 画布从左到右逐模块推进；轮到你放行的连接件会亮起，点节点页的裁决条操作。

### 看模块结果并批注
点模块色块 → 看「模块结果报告」（验收三态 + 指标）→ 点开交付件阅读 → 不满意就在文末批注框写意见 → 意见自动汇入审核意见簿，并进入优化提案池。

### 批准或驳回优化提案
编排面板（或连接件/边界门页）看「优化提案 · 待批」→ 逐条批准或驳回 → 批准的改动由流程引擎重编译计划生效。**任何提案都不会未经你批准自动生效。**

### 导出交付文档
产物管理 → 模块交付 / 交付件 → 「下载/打开」。Word 文档（docx）由交付模块的脚本导出，带完整排版。

### 重跑某个节点
点开节点页 → 工具条「重跑」→ 选择范围（从本节点重跑到模块验收门 / 整个模块从零）。内容没变的上游走缓存，不重复消耗。

## 五、徽章与状态图例

| 图例 | 含义 |
|---|---|
| 🟢 圆点 | 节点已完成 |
| 🟡 圆点 | 待决（等提交 / 等你放行） |
| ⚪ 空心 | 未启动 / 待重跑 |
| `效率 0.8`（绿） | 该工位产出被下游消费良好 |
| `效率 0.2`（红） | 产出很少被用——优化候选 |
| `命中 60%`（绿）/ `30%`（黄）/ `0%`（红） | 写作标准被产物真实引用的比例 |
| `未采样` | 该工位尚无运行数据（诚实标注，不编数） |
| 金色实线连接件 | 人工放行检查站 |
| 灰色虚线连接件 | 自动放行 |
| `✓ / …`（交付清单核对） | 已产出 / 待产出 |

## 六、指标口径（人话版）

- **命中率** = 产物真正引用了的写作标准 ÷ 注入给它的标准。双层口径：**字面层**（产物明确引用了哪条标准）+ **概念层**（产物正文落实了标准的核心概念词）。页面展示的是两层合计；老项目的历史数字是旧口径（仅字面），新跑的项目自动用新口径。
- **tool 效率** = 被下游真正消费的次数 ÷ 成本。成本 = token 消耗 + 耗时 + 打回与重试的返工溢价。
- **验收三态** = pass / warn（黄，建议但不阻塞）/ block（打回）。机器查不了的维度（如"代入感"）标 unverified 交人工评审，**绝不冒充通过**。

## 七、已知边界 · FAQ

- **打开旧项目，画布是空的 / 提示 bootstrap？** 该项目跑在旧版流程引擎上。按横幅里的命令重跑一次 `flow_effect` 即可看到模块化画布；盘上旧数据不会被动。
- **「中间件」点进去是空的？** 本流程没有产出世界书目录——它的设定职责由编剧模块的《世界圣经》过程件承担（在文档架的过程件里）。按钮文案会注明。
- **交付的 Word 在哪？** 文档架顶部「交付件」区或产物管理的「模块交付」区，点「下载/打开」。
- **我看到一个节点显示「未归属」？** 页面数据与流程引擎不同步的显式提示——跑一次 `flow_effect` 刷新即可。
- **为什么有的检查显示 unverified？** 那些维度机器查不了（比如"情绪是否到位"），系统诚实标出交人工评审，不会假装通过。
- **提案批准后能撤销吗？** 项目改写有完整历史记录，可回滚；提示词类改动全部走"提案→人批"两步，不会闪改。
