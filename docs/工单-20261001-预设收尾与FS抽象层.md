## R7 · FS Phase 4：包拆分发布

**任务分解**：
1. `@storyflow/core`（无 node:* import）+ `@storyflow/adapters`（Node/Virtual 适配器）workspace 拆包
2. 旧入口（`core/src/*` 路径）re-export 兼容，CLI/MCP/HTTP 启动脚本零感
3. 迁移说明（不写自动迁移脚本——消费者当前只有本仓库与 adapter/，人工过一遍即可）

**验收门禁**：core 包在无 `@types/node` 的 tsconfig 下 tsc 通过；根仓 tsc+vitest 全绿；`storyflow http` 冒烟启动。

**R7 开工前实测（R6 收口时顺手量的，2026-09-30，三条都影响上面这道门禁的写法）**：

1. **这道门禁按字面跑是空转的**。把 `core/tsconfig.json` 的 `types` 置空再编整个 `src`：`tsc` **0 error**——
   可盘面明明还有六处 `node:*` import。原因：`@fastify/cors`、`@fastify/proxy-addr`、`@modelcontextprotocol/sdk` 一路下来的 d.ts 带着
   `/// <reference types="node" />`（`grep -rl '<reference types="node"' node_modules --include="*.d.ts"` 可复现），
   只要 fastify/MCP SDK 还在依赖图里，`@types/node` 就会**传递性进场**，`types: []` 拦不住。
   ⇒ R7 的门禁得换成两条能落地的：**① import 普查**（`r6-host-free.test.ts` 的双向死表，FS 族零＋非 FS 族按名单）；
   **② 真无 node 编译**——core 包必须把 fastify/MCP SDK 留在包外（宿主适配面），否则「无 `@types/node`」永远只是自证。
2. **六处里有一处疑似死码**：`kernel.ts:577-578` 的 `const require = (await import("node:module")).createRequire(import.meta.url)`
   ——全仓除这两行外**查无 `require` 调用点**（`grep -rnw "require" core/src --include="*.ts"` 只命中它自己），注释说的「供 viewJournal 惰性 require」已不在盘上。
   R7 第一步先验尸：确认死码就删（六处变五处），别为它造适配器。
3. **core 包的宿主面不止 `node:*` import**（拆包时按这几处一起处置，不然 core 只是名义上干净）：
   `process.env` **5 个文件**（`aesthetic.ts` `agent.ts` `asserts.ts` `compat.ts` `verbs.ts`）、
   `Buffer` **1 个文件**（`compat.ts:69` 的 base64 摘要）、`console.*` **1 个文件**（`verbs.ts`）、
   `ids.ts::sha12` 是**同步** sha1（WebCrypto 的 `digest` 是异步，不能就地换——要么纯 JS sha1 进 core，要么把 `sha12` 归适配器）。
   这四类都在 FS1 §六 D7 的「宿主面不进 v1」名单里，当初不算漏，现在正是 R7 的活。
4. **依赖图实测（拆包边界就长这样）**：`grep -rln 'from "<pkg>"' core/src` 逐包点名——
   fastify：`http.ts` `api-v1.ts` `compat.ts`；`@fastify/cors`：`http.ts`；`@modelcontextprotocol/sdk`：`mcp.ts` `agent-mcp.ts`；
   ajv：`schema.ts`；js-yaml：`assertion-preset/{discovery,resolver}.ts` `production-preset.ts`；zod（**传递依赖**，R4 回执 U3）：`mcp.ts` `verbs.ts`。
   其中 `api-v1.ts` 与 `compat.ts` 只是 `import type { FastifyInstance … }`（编译期擦除，但**类型仍要包在场**，而 fastify 的 d.ts 正是 `@types/node` 的传递入口）。
   ⇒ core 包要真正与 node 类型解绑，这两个文件的 fastify 形状得换成本地结构化类型（或把 HTTP 面整体挪进 adapters 包），
   不是加个 `types: []` 就能了事的。

**预估**：1 天。**依赖**：R6（已交）。
