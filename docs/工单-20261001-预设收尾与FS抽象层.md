## R3 · FS Phase 1：内核核心改造（8+ 文件）

**目标**：Kernel 构造注入 `fs`/`path`；P0 文件迁移；fsio.ts 退役。**注意 0.10.0 拆分后的现实：P0 集合 = kernel.ts + kernel-{run,view,optimize,config}.ts + minitools/state/registry/asserts/project-config/compat。**

**写集**：上述 10 文件 + `core/src/fsio.ts`（删除）+ 全仓 `fsio.js` import 更新 + `core/src/kernel.ts`（KernelOptions 增 `fs?/path?`）。

**关键设计**（实现前定稿）：
- 模块级函数（state/registry/asserts 等非类方法）**不引全局单例**——沿用拆分模式，函数签名增 `fs: IFileSystem = nodeFs` 尾参，调用方从 kernel 透传。显式、可测、与 `kernel: Kernel` 传参风格一致。
- `atomicWriteText` 等语义并入 `NodeFsAdapter`，fsio.ts 删除后所有 import 改指适配器（或 kernel.ts re-export 一版过渡）。
- `spawn.ts` / `compat.ts` 的 execFile/spawnSync 改消费 `IProcessLauncher`（NodeProcLauncher 为缺省）。

**任务分解**：
1. KernelOptions + 构造注入 + kernel.ts 自身迁移
2. kernel-{run,view,optimize,config} 迁移（ctx/persist 链优先）
3. state/registry/asserts/project-config 迁移（签名尾参）
4. minitools + compat/spawn 的 proc 抽象
5. fsio.ts 退役 + import 面清理
6. 冒烟：`abstraction-smoke.test.ts` — MockFsAdapter + MockProcLauncher 上跑通 topic 流 flow_run → flow_submit（**「可嵌入」的第一次真证明**）

**验收门禁**：全量绿零回归；冒烟测试过；`grep -rl "node:fs" core/src` 只剩 `abstraction/`（cli/http 等外围 P3 文件临时豁免，列清单进 R6）。

**预估**：2 天。**依赖**：R1。
