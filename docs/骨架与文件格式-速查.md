# 骨架与文件格式速查（flow@3 · R6）——给人和 agent 的一页纸

> 装配规则详解见 `skills/flow-synthesize.md`；契约真相：`contracts/flow.schema.json`（冻结）。
> 任何草稿落盘前：`python tools/skeleton-lint.py --file <草稿> --fix-hint`。

## 一 · 模块清单（modules/<id>/module.json，8 个）

| 模块 id | 工种 | 默认骨架（spine） | caps（能力标签全集） |
| --- | --- | --- | --- |
| `topic` | 选题 | find-trope → material-dissect | 找梗 · 素材解剖 · 时代情绪锚 · 网感文案 · 拆书入库 · 热点采集 |
| `plan` | 方案 | topic-analysis-report → topic-proposal | 选题分析 · 选题方案 · 审美终审 · 交付对账 |
| `plot` | 编剧 | structure-design → plot-choreographer ← novel-bible → scene-breakdown | 结构 · 主线 · 人设 · 分场 · 世界观 · 单元剧大纲 · 短剧节拍 · 暗线 · 伏笔 · 悬念 · 红队评审 |
| `prose` | 写作 | layer-voices → layer-scenes → layer-canon → prose-assembler → novel-deai | 台词层 · 场景层 · 设定层 · 拼装盖章 · 终稿打磨 · 去机味 · 直写单章 · 剧本成稿 · 对话打磨 · 文学评审 · 视频提示词 |
| `delivery` | 交付 | export-doc | docx交付 · 交付页 · 批注回流 |
| `search` | 检索 | （无骨架；内核挂载） | 知识装载 · 知识检索 · 条目读取 · 产物读取 |
| `detect` | 检测 | （无骨架；按 caps 启用） | AI味打分 · 朱雀对照 · AI味扫描 |
| `base` | 底座 | （机器域） | **永不进 flow 序列** |

不写 `caps` = 只跑默认骨架。**差值即可玩空间**：骨架没覆盖的能力，写进 caps，内核自动挑工具接线。

## 二 · flow@3 最小示例（~15 行）

```json
{
  "format": "flow@3",
  "id": "min-flow",
  "title": "最小示例",
  "version": "1.0.0",
  "status": "official",
  "defaults": { "link": "auto" },
  "modules": [
    { "id": "m1", "module": "topic",  "link": "auto",  "caps": ["找梗"] },
    { "id": "m2", "module": "plot",   "link": "manual", "caps": ["主线", "伏笔"] },
    { "id": "m3", "module": "prose",  "link": "auto",
      "iterate": { "unit": "chapter", "over": "卷纲", "first": 1 } },
    { "id": "m4", "module": "delivery", "link": "auto", "caps": ["docx交付"] }
  ]
}
```

实例字段速记：`link`=进入本模块的连接件（auto 放行 / manual 挂起等人，reject=重跑整个上游模块）；`caps`=要什么能力；`insert`=`{"after:<tool>":["<tool>"]}` 钉插槽；`iterate`/`vary`=按章卷集重复与逐单位差异；`when`=绑 inputs 的可选开关。

## 三 · 项目文件布局（R6 §五）

```
projects/<id>/
├─ 输入/            人写：点子 / 素材 / 需求
├─ 世界书/          跨模块共享：设定 · 人物 · 时间线 · 词表.json
├─ 01-选题/ 02-方案/ 03-编剧/ 04-写作/   模块产物就地（NN=模块序号；意见书也在这）
├─ 交付/            NN- 定序交付出口（终稿才进；不再有 flow.outputs）
├─ registry/        机器：生效编排 / 指标 / 产物索引 / receipts/（收据统一在这）
└─ snapshots/       机器：快照（不可改写）
```

artifact 头部八项：`artifact/id/module/node/state/at/by/upstream`（`class/round/version` 已废；`review` 只在 manual 连接件放行后写，挂 `link`）。

## 四 · 三个常见错误

1. **把 flow@2 的 `graph/stages/outputs` 带进 flow@3**（skeleton-lint E-SCHEMA）。模块序列取代手画图；交付物不再声明 outputs——落 `交付/` 目录，NN 按模块序。
2. **caps 里写工具名或自造能力词**（W-CAPS）。caps 是人类能力词（主线/暗线/伏笔…），必须在目标模块的 caps 表内；没有的能力=尚未工具化，回来问用户，禁止硬凑。
3. **把 `link:"manual"` 当装饰**。manual 是整段挂起等人 pass/reject，reject 重跑整个上游模块——只放在方向性闸口（选题→方案、编剧→写作、写作→交付），滥用会把流水线变人肉闸门。
