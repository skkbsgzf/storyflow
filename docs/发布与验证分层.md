# 发布与验证分层（打包验证 / 工作区改跑）

> 解决的问题：本地改本地验，验证目标跟着开发漂——页面看一半内容变了、外发评审看到半成品、
> 双进程串台。分层后**验证指向冻结包，开发指向工作区**，互不踩脚。

## 两层分工

| 层 | 端口 | 内容 | 用途 |
| --- | --- | --- | --- |
| **开发层** | 8420 | 工作区原目录（`serve.py` 默认根） | 新代码改和跑；写作线程出产物；页面随时重生成 |
| **验证层** | 8430 | `dist/release-<commit>-<时间>/`（冻结快照） | 验收、回归、外发评审——指向它的链接永不变质 |
| 外发层 | 8427 | 同验证层机制 + `--code` 邀请码门 | 给甲方/评审的受限入口 |

## 命令

```bash
python tools/package.py --start 8430            # 打包 + 启动验证实例
python tools/package.py --start 8431 --code X   # 带邀请码的验证实例
python tools/serve.py 8420                      # 开发层（工作区原目录）
```

打包器做的事：① 先用当前盘上真相**重生成全部项目页**；② 冻结拷贝
`tools/flows/kits/knowledge/skills/contracts/templates/docs/core` + 各项目
（**排除 snapshots/registry/journal**——运行时账本不进包）；③ 写 `MANIFEST.json`
（commit/dirty/文件数/入口命令）；④ 可选拉起验证实例。

## 升级循环

```
工作区改代码/改稿 → 门禁全绿（flow-lint/kit-lint/vitest/page-lint）
  → python tools/package.py --start 8430   # 重打包，验证实例换新包
  → 验证意见 → 回工作区修 → 再打包
```

- 验证层报的问题回到**工作区修**，修完重打包；禁止在 dist/ 里直接改（下次打包会被覆盖）
- `MANIFEST.json` 的 `dirty=true` 表示打包时工作区有未提交改动——正式外发前先提交
- 旧包保留在 `dist/` 下按版本名共存（`--keep` 可跳过清理）；`dist/` 不进 git

## 边界

- 包内是**拷贝**：验证实例上的批注/意见保存（`/_kit/save`）写进包副本，不会回流工作区；
  需要回流时走审核意见簿导出，或直接在开发层操作
- `core/` 以源码进包（CLI 重跑用），`node_modules` 不进；重跑仍需在包目录装依赖或指向工作区
