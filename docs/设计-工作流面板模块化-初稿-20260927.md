# 设计初稿 · 工作流面板模块化（2026-09-27 · 甲方拍板口径落地）

> 甲方口径（2026-09-27 语音转述）：**每个模块是一个封装好的工作流；模块之间不再强绑定连接顺序，
> 由 Agent 在执行时调度**——用户说「把这个流程重跑一下」，Agent 自行判断重跑范围。面板形态 =
> **展示一个模块、可切换不同模块、可查看管理模块**；Agent 执行时能感知模块间关联性即可。
> 本文 = 面板初稿设计 + 实现记录；E-A 工单 A2.3 的「深度嵌入二轮另议」就此改口径（见 §5）。

## 1. 概念对齐：底座已经长了一半

| 甲方概念 | 底座现有对应物 | 缺口 |
|---|---|---|
| 模块 = 封装好的工作流 | module@1（`modules/<id>/module.json` 能力注册表）+ flow 节点的 `kit+op` 引用 | 无 |
| 模块间关联可感知 | `registry/effective.json` 的 `links[]`（阶段连接门）+ `edges[]`（跨模块边）——**已是内核落盘事实** | 面板从未渲染过 |
| 模块间**不强绑定顺序** | flow@3 的 stage 硬序 + link gate（人工裁决点在 kit 边界） | **编排格式演进，本轮不动**（§6） |
| Agent 调度模块 | pi 单脑对话环（`/api/projects/:id/agent/turn`）+ mf_* 工具环 | 面板缺一个「把调度意图交给 Agent」的入口 |

**本轮口径：面板先按目标形态渲染（软关联、模块为中心、Agent 调度入口），内核与 flow 格式不动。**
用真项目的面板 + Agent 闭环攒体感，再决定编排格式怎么软化——先产品后协议，避免格式先行空转。

## 2. 面板信息架构（右栏「工作流」页签，原生渲染，iframe 移出右栏）

```
┌─ 右栏 360px ──────────────────┐
│ [选题 6/6] [剧情 11/11] [分镜 1/1]   ← 模块切换器（chip，按生效编排出现序）
│ ──────────────────────────── │
│ 「选题」模块 · 6 节点 · 6 完成      ← 模块头
│ [↻ 让 Agent 重跑此模块] [⤢ 画布]  ← 调度入口 + 全屏逃生口
│ ──────────────────────────── │
│ ✓ 选题报告师  topic-report · 83s    ← 节点实例（状态点+中文名+op+耗时）
│ ✓ 梗卡检索师  find-trope · 48s      │ 点击展开详情：
│ ✓ 素材解剖师  material-dissect 32s  │   desc / 状态轮次 / 遥测明细
│ …                                   │   产物文件 → 点击跳「文档」面板看正文
│ ──────────────────────────── │
│ 模块间关联（调度参考，非固定顺序）：  ← 软关联段
│ → 阶段 m2 · mode:auto（连接门）      │   数据源 links[]（阶段连接门）+ 跨 kit 边
└─────────────────────────────┘
```

- **状态点**：✓ done ｜ ● running/其他 ｜ ⚠ stale（编排改写后待重算）｜ ○ pending。数据 = `state.json.nodes`
- **证据列**：耗时 / judge flagged 数（⚖n）= B3 遥测逐节点匹配
- **产物跳转**：节点产物路径 → 文档面板直接打开该文件（跨面板闭环，复用 B2 单文件读取）
- **重跑 = 对话接管**：按钮把调度指令填入对话输入框并**直接发送**给 pi 单脑（「重跑「选题」模块：
  先感知现有产物与上下游关联，自行判断重跑范围与方式，逐节点重做并交卷」）——面板自己不重跑
  （R5：编排事实单源在内核，Agent 是调度者）；人只按一下「说这句话」的按钮
- **全屏画布（逃生口）**：`⤢ 画布` 弹 fixed 全屏 overlay，iframe 嵌 8421 现页——全屏下作业台 chrome
  合法；Esc/关闭钮退出。**右栏内不再有 iframe**（双层 chrome / 吞滚轮 / 360px 放不下图，三罪并罚）

  （B2 只读项目内；工作区级模块注册表要等 `/api/panel/modules` 或内核动词，列入 B 组待派）

## 7. 实现期追加 · B5 画布同源代理（白屏根因修复）

全屏画布首测**白屏**：8421 页面单开正常、响应头无 X-Frame-Options/CSP、load 事件正常触发，但跨源
iframe（8432→8421）里初始化崩掉。根因定位：作业台页初始化访问 `localStorage`（9 处），跨源 iframe
的第三方存储被拒 → 初始化抛异常 → 整页不渲染。而页面 API 基址是烘焙的绝对 URL（`DATA.agentApi`），
不依赖自身 origin——于是：

- **B5 `GET /api/panel/canvas?project=<id>`**（panels.ts + serve.ts panel 段各一支）：把
  `<projectDir>/workflow.html` 以 **同源 text/html** 供出（200 / 798955B 实测过）。iframe 改走
  `/api/panel/canvas?project=<id>` → localStorage 变第一方，白屏消失，附带 iframe 同源化
  （Esc 监听可进 iframe 文档、未来可深度交互）。
- 8421 直连 URL 弃用；作业台页内部 API 照旧打 8431/8421 绝对基址（CORS 全开，行为不变）。

## 10. 内容融合（2026-09-28 甲方拍板「融合一下」）

甲方指出：右栏三面板（世界书/工作流/文档）与分屏窗格「选择内容」是两套割裂机制——窗格该呈现的
就是右栏那批内容。融合落地（home.ts 17+1 处批改，tsc 0E + 23/23 绿，仍未提交）：

- **内容注册表 `CONTENTS`**：`[wb 世界书, cv 工作流, fl 文档, traj 轨迹, web 浏览器]` 五项——
  右栏页签与窗格选择卡共用同一清单；窗格选择卡从 3 张扩到 5 张（补上世界书/工作流）。
- **渲染器统一带宿主参数**：`loadWB(host) / loadFL(host) / showFileContent(path,host) / loadCV(host)
  / renderTrajInto(el)`——host 缺省落右栏面板，传 `#p2-body` 落窗格；renderCV 经 `CV.host` 记住宿主
  （chip 切换/节点展开/产物跳转全部原地）。**产物点击在窗格里就留窗格**（不再强切右栏文档页签）。
  主区轨迹页签也改走 `renderTrajInto`（三处消费一个实现，`p2Traj/p2Files` 重复实现删除）。
- **分屏 = 右栏让位**：开分屏自动收起右栏（同一批内容不再两处并存）；关窗格/关分屏右栏回归并重载。
  重开分屏**刷新上次内容**（`p2Open(P2.kind)`），无上次内容出选择卡。
- web 浏览器卡仍走 p2Web（flex 布局 iframe），其余四卡走 block 流式布局（`#p2-body` 改 overflow:auto）。

浏览器实弹（p-kunxiu-001）：分屏→右栏 hide→选择卡 5 张；窗格世界书 27 词条+词条详情+返回；
窗格工作流 4 模块 chip+节点展开；节点产物点击**留在窗格**（右栏页签不动）；关窗格→右栏回归且
