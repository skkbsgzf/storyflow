**A1 · 通道 A 的 Chrome 原生 `showDirectoryPicker` / `createWritable`**（缺口已收窄到只剩浏览器自己的那一段，见下）

## B 组 · 越界一记（顺手修了不属于本单的东西，请裁是否保留）

**B1 · `tools/kb-graph-template.html` 图谱边静默丢弃**
W4.1 做看板 RAG 区时发现：模板里 links 用 `idxOf.get(l.s)` 查表，而 `build_payload` 产出的 `links[].s/t` 是节点下标（整数），恒查不到，结果是**图谱页所有边被静默丢弃**（p-menghe-01 实测 payload 23 边、页面渲染 0 边）。我改成了下标/id 双形态兼容认。这个 bug 对生成器自己的 `--selfcheck` 不可见，因为自测只校验 Python 侧 payload，不校验浏览器渲染。
证据：`CHANGELOG.md` W4.1 段第 5 条、`docs/工单-20261012-批次4-项目看板与湮灭批次2.md:16`。
取舍：案① 保留（推荐，这是真 bug 且只放宽不收紧）；案② 回滚，另立工单交原线。回滚成本很低，一条 `git checkout` 就行，但图谱页会继续 0 边。

**B2 · `adapter/storyflow-client.mjs::login()` 从 `Set-Cookie` 抠 token 转 Bearer**
W4.2 实测 `fileWrite` 时撞出一个既存缺口：`/api/login` 的 token 只落在 HttpOnly cookie 里（响应体只有 `{ok,ttlHours}`），而 Node/Electron 主进程的 `fetch` 没有 cookie 罐，于是参考客户端登录后依旧 401——**任何非浏览器宿主都走不通带口令的能力面**，不只是写端点。我改在客户端侧收口：`login()` 从 `Set-Cookie` 抠出 `sh_token` 转走 Bearer，返回值加 `tokenVia` 记录走的是哪条路（body / set-cookie / none），服务端零改动，token 仍然不进响应体（不进日志与代理缓存）。浏览器侧行为不变。
证据：`CHANGELOG.md` W4.2 段第 11 条、`docs/工单-20261012-批次4-项目看板与湮灭批次2.md:60`、收据 `projects/_reports/w42-adapter-client-filewrite-20261012.json`（11/11）。
取舍：案① 保留客户端收口 + 另立服务端工单做正式方案（推荐，未来 kit 要被 workbuddy 等宿主发现调用，这条线早晚要正名）；案② 服务端在 `/api/login` 响应体回 token（代价：token 进响应体，也就进调用方日志与代理缓存面）；案③ 回滚，非浏览器宿主继续只读。
