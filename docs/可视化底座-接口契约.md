# miniflow 内核 HTTP 接口契约 · 交官方可视化底座（v1 冻结）

> 交接方：内核线程（M1）→ 接收方：官方可视化底座线程
> 契约文件：`contracts/http-openapi.json`（OpenAPI 3.1，本文件是人读摘要；冲突以 OpenAPI + contracts/ schema 为准）
> 日期：2026-09-16 ｜ 内核版本 0.1.0

## 启动

```bash
cd core && npx tsx src/http.ts --port 8421   # REST + CORS 全开
# 或装好依赖后：node dist/cli.js serve --port 8421
```

基准地址 `http://127.0.0.1:8421`。CORS 已放开（已验证 8420 来源的预检），可视化前端可直接跨域消费。

## 端点

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/projects` | 项目列表：projectId / flowId / status / focus / gateAwaiting / pendingCount / migrated |
| GET | `/api/projects/{id}/state` | run 状态机全文（`contracts/run-state.schema.json` v1.0.1） |
| GET | `/api/projects/{id}/graph` | flow 描述符（节点 kind/title/skill/minitool、边 when/optional、stages、inputs/outputs）——画布直接消费 |
| GET | `/api/projects/{id}/artifacts?node=&latest=` | 产物注册表条目（sha1 / 输入指纹 / 校验结果） |
| GET | `/api/projects/{id}/artifacts/content?path=` | 产物全文（**仅限已注册路径**——未注册 403，"未注册=不可读"是纪律不是缺陷） |
| GET | `/api/projects/{id}/journal?since=&limit=&node=` | 事件流（run-start/advance/submit/reject/gate-open/verdict/stale/snapshot…） |
| GET | `/api/projects/{id}/snapshots/{node}` | 节点快照轮次 + 每轮文本内容（与 tools/snapshot.py 的 index.json 同源） |
| GET | `/api/projects/{id}/config` | **读项目初始化配置**（v1.1）：`{exists, config?, template, boundWarning?}`。无文件时 `template` 即表单初始值；字段中键（题材/需求/灵感/严肃性/风格/AB测试/市场预估）与 `项目配置.json` 一一对应，表单直接绑定 |
| PUT | `/api/projects/{id}/config` | **保存项目初始化配置**（v1.1）：表单整体提交，schema 校验（400=非法）；`boundWarning` = run 已绑定的字段修改仅对重跑/下次 flow_run 生效 |
| GET | `/api/projects/{id}/workbench-payload` | **兼容桥**：与现 workflow.html 的 `DATA` 同构（{flow, files, runstate, project, snapshots}），旧页面渐迁用 |
| POST | `/api/projects/{id}/gate` | 人工裁决：`{nodeId, verdict, comment?, rootCauseStage?, round?, token?}`；send-back 级联失效；round/token 不匹配 409 |
| POST | `/api/projects/{id}/rerun` | `{nodeId, dryRun}`：受影响子图推演/执行 |
| GET | `/api/openapi.json` | 本契约自描述 |

## 写回纪律（重要）

1. **前端不直写项目文件**。裁决走 `POST /gate`、重跑走 `POST /rerun`；宿主（agent）的产物提交走七动词（CLI/MCP）或 `POST /api/verbs/flow_submit`。旧页面用 File System Access API 直写 run-state.json 的模式**不再使用**。
2. 旧 `runstate` 形状的字段全部保留在 `state.json`（nodes[].status/round/verdict/note、gate、presets、comments、inputs），旧渲染逻辑的读路径基本可平移；差异点：新增 `plan.order`、`focus`、`lastRejectReason`，节点可能多出 `stale`/`rootCauseStage`。
3. 未迁移项目（仍是 run-state.json）在 `/api/projects` 里 `migrated:false`；对其执行一次 `POST /api/verbs/flow_run` 即自动迁移（旧文件保留供审计）。

## 边界（内核 M1 未做，勿依赖）

- 美学断言（check_aesthetic_asserts 66 条）与词汇表守卫：M2 接入（当前完整性断言已在，report 里 `mode:"integrity"`）；
- rerun 的输入指纹缓存命中：M2 全量（当前为范围推演+级联失效）；
- 批次展开（novel-longform 逐章循环）：内核已有 `batch` 派发位（`awaiting_input.batch[]` + `parallelWith`），批次图展开语义另行协调。

## 联调节奏建议

1. 可视化线程先接 `GET /api/projects` + `/state` + `/graph`，替换静态 payload；
2. **初始化配置表单（v1.1 新增）**：项目详情页做「开跑配置」面板——GET `/config` 拿 `template ?? config` 填表，PUT `/config` 保存；表单字段与 `项目配置.json` 中键一一对应（契约 `contracts/project-config.schema.json`：题材/需求/灵感/严肃性[探索|标准|出品]/风格[爽|标准]/AB测试[bool]/市场预估/presets）。`boundWarning` 非空时在表单顶部展示提示条；
3. 快照/产物预览接 `/snapshots/{node}` 与 `/artifacts/content`；
4. 裁决/重跑接 POST 端点（替代旧页面的 verdict 直写）；
5. 全部通后废弃 workbench-payload 兼容桥。
