# subagent 派发质量分析报告 R1

> 触发：甲方观察到重跑双项目的 8 个 subagent「有很多工具和上下文，项目背景没有弄清楚」
> 范围：S1 重跑中经 Agent 工具派发的全部 8 个子代理（4 研究批 + 2 分析 + 2 红方）
> 日期：2026-09-16 ｜ 关联：底座规格 §2.3（任务包即上下文）、docs/subagent-并行调度.md

---

## 一、结论（TL;DR）

**子代理「弄不清项目背景」不是模型能力问题，是派发协议断了链**：内核的任务包机制（instruction + 哈希锚定上下文 + 剖面 + 预算）是为 subagent 设计的，但实际派发时宿主（主 agent）**绕过了任务包，手写了「文件路径清单」式 prompt**——子代理拿到的是一堆"必读路径"而不是组装好的背景与上下文，只能自己考古拼背景。量化佐证：找梗师为写一份梗卡花了 **31 次工具调用 / 45 万 token**，而它的全部输入只有 3 个小文件。次级问题：工具面全开、负面禁令靠自觉、无背景理解校验、子代理思维链不落盘无法审计。

## 二、证据

### 2.1 用量数据（8 个子代理）

| 子代理 | 任务 | 工具调用 | tokens |
| --- | --- | --- | --- |
| 拍魂·找梗师 | 梗卡.md | 25 | 325,591 |
| 拍魂·网感师 | 热点素材.md | 14 | 210,381 |
| 守堤人·找梗师 | 梗卡.md | **31** | **450,288** |
| 守堤人·网感师 | 热点素材.md | 10 | 166,996 |
| 拍魂·分析师 | 选题分析报告.md | 9 | 260,738 |
| 守堤人·分析师 | 选题分析报告.md | 8 | 174,842 |
| 拍魂·红方 | 意见书-R1 | 9 | 236,364 |
| 守堤人·红方 | 意见书-R1 | 6 | 102,680 |
| **合计** | | **112** | **≈193 万** |

两个相关性信号：① 输入只有 3 个文件的找梗师最贵（31 次调用）——它要自行解决「背景是什么」；② 红方拿到了最收敛的必读清单，只用了 6-9 次——**派发信息的收敛度与探索成本强相关**。守堤人找梗师甚至在 bash 引用上浪费了循环（其交卷摘要自述"报错仅为 bash 吞掉 $b 变量所致"）——工具面全开的摩擦成本实锤。

### 2.2 审计缺口

8 个子代理中 **0 个有完整思维链落盘**（rollout 只有 2 份他线程的子代理日志；exec/ 目录为空、artifacts 只存单个大工具结果）。本次"背景没弄清楚"的结论依赖甲方人肉观察 + 用量间接推断——**子代理思维链应像 run 一样可回放**，否则裁决与复盘永远缺原料。

### 2.3 派发原文特征（8 份 prompt 共性）

- 角色一句话 + 「必读」文件路径清单 + 负面禁令 + 写盘路径；
- **没有**：项目是什么的一段话陈述、当前所处阶段与验收标准、产出物给谁用、上游产物结论摘要、词汇表/合规速查；
- 全部为宿主手写——8 份之间格式漂移，且与内核 `flow_next` 返回的 `taskPackage`（内含 instruction 全文 + 哈希锚定上下文 + profile）**完全脱节**。

## 三、根因分析

| # | 根因 | 机制层面的解释 |
| --- | --- | --- |
| **R1** | **派发绕过任务包**（总根因） | 内核组装的任务包被丢弃，宿主手写 prompt——「任务包即全部上下文」纪律在 human-agent 派发路径上没有执行点。这与最早的事故（agent 绕过 harness 凭记忆干活）同构：正确的方式不是最顺手的方式 |
| R2 | 无「项目背景卡」 | 任务包只有上游产物摘录，缺一段综合陈述：项目身份/阶段问题/交付物用途/合规红线/own 词汇。子代理被迫用 20-30 次文件考古自行合成，且每次合成的理解不可复用、不可校验 |
| R3 | 工具面全开 | general-purpose 拿全部工具（git/浏览器/定时任务…），无 allowed-tools 声明。探索面 = 干扰面 = 摩擦面（bash 引用事故即例证） |
| R4 | 负面禁令靠 prose 自觉 | 「禁止读 _archive」写进提示词，但没有可见性隔离。子代理仍会列出目录、犹豫、绕行——禁令本身成为上下文噪音 |
| R5 | 无理解校验 | 子代理不需要证明「弄懂了背景」即可动笔；理解偏差要到终稿才暴露，返工成本最高 |
| R6 | 思维链不落盘 | 子代理会话无 transcript 持久化，甲方观察是我方唯一审计手段——这直接违反底座「journal 可回放」哲学 |

## 四、优化方案（按层）

### 内核侧（确定性，优先做）

- **K1 任务包新增「项目背景卡」**：`assembler` 组装一段确定性文本——项目 id/名称、flow 阶段与阶段问题（flow.stages[].question 现成有）、甲方点子摘录（选题素材.md 头部 N 字）、本次交付物的用途与下游、上游产物一览（done/pending）、词汇表 own 词与 banned 红线。全部来自盘上文件，哈希锚定，零发明。
- **K2 「派发头」生成器**：`flow_next --spawn-prompt`（或 minitool）把 任务包 → 一段规范 spawn 文本：`role/mission + 背景卡 + context[] 摘录 + 输出契约 + 工具纪律 + 负面禁令 + 交卷格式`。宿主复制即用——**让正确的方式成为最顺手的方式**（R1 的真正解法）。
- **K3 工具面最小化**：profile 契约增加 `tools: ["Read","Write","WebSearch"]` 声明；宿主按剖面选择执行器并在派发头写明「仅允许使用以下工具」。宿主侧做不到硬隔离时，至少把工具清单从"全部"收敛为剖面声明集。
- **K5 子代理思维链落盘**：子代理会话 transcript（或至少每次工具调用摘要）写入 `projects/<id>/journal`（event: `subagent`，refs: 派发任务包哈希）——审计与复盘原料齐备。

### 宿主派发协议（SOP）

- **H1 派发只认任务包**：spawn prompt = `K2 派发头` 原样 + 一句「把产物写入 {file}」；禁止手写「必读」清单（手写=绕过纪律=本次事故）。
- **H2 背景复述校验**：交卷摘要首行必须复述背景卡四要素（项目/阶段/交付物/受众）——不符即弃稿重派，理解偏差在最早时刻暴露（R5 的解法，成本一行字）。
- **H3 可见性收敛**：派发头明确工作集 = 本项目目录 + 指定知识条目；其余路径声明为「不存在」。

### 剖面侧

- **P1 剖面补 `tools` 与 `backgrounding` 字段**：每类角色声明最小工具集与背景卡必读段（如红方不需要市场 KB 全文，只需要被审对象）。

## 五、量化预期

| 指标 | 现状（本次） | 目标 |
| --- | --- | --- |
| 找梗师工具调用 | 25-31 次 | ≤10 次（skill+素材+2KB+写盘+校验） |
| 单子代理 tokens | 10-45 万 | ⅓ 量级 |
| 背景理解 | 自行考古，不可校验 | 背景卡直给 + 首段复述校验 |
| 思维链审计 | 无 | journal 可回放 |

## 六、落地顺序

1. **K1+K2**（背景卡 + 派发头生成器）——一个 assembler 扩展 + 一个 CLI flag，半天量级，直接消灭 R1/R2；
2. **H1+H2**（宿主 SOP）——零代码，纪律条目进 AGENTS.md；
3. **K3+P1**（工具面最小化）——契约扩展 + 派发头字段；
4. **K5**（transcript 落盘）——需要宿主端配合截获子代理会话，排 M2 收尾。

> 一句话：**底座已经有任务包，但派发的人没有用任务包。** 先让派发头成为唯一派发方式，再谈更聪明的上下文。
