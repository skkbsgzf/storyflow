# 亮点闭环（卖点 → 台词范式 → 成文消费）

> 立场：**心声类作品很多，创新的很少**。创新点不在"能看到心声"这个机制，而在心声**说什么、怎么说**——
> 即现代用户对 AI 生成对话的集体梗记忆。这类台词与梗的设计必须在 **research/大纲阶段**完成定义，
> 通过 flow 传递给文学模块成文，才算亮点闭环；临到写正文再想梗 = 亮点漏光。

## 一、为什么是 AI 语音梗（2025-26 集体笑点记忆）

AI 生成对话的用户梗是当下最热的公共语料，辨识度极高、零解释成本：

- **豆包式礼貌绕弯**：永 远 在 客 气，用最周到的措辞说最敷衍的话（"让我用最不绕弯子的方式告诉你"→然后绕了八个弯）
- **DeepSeek 摸鱼思维链**：一边干活一边自言自语摆烂（"先这样吧，剩下的下次再说"、"这个问题太复杂，我决定先睡一觉"）
- **客服工单腔**：您的反馈已收到 / 当前排队第 99 位 / 感谢您的理解
- **免责声明腔**："该评价仅代表个人立场"、"本回答不构成任何建议"
- **系统告警腔**：⚠ 检测到异常 / 评级下调 / 触发风控
- **App 评分腔**：本次服务 2.1 星 / 好评返现 / 差评威胁

## 二、台词范式（映射到「万物差评」心声的写法样本）

心声 = 系统（神）给万物打的差评/工单。AI 语音梗的笑点 = **官方话术的程式化礼貌 × 真实意图的刻薄**之间的反差。
范式样本（写法示范，不是定稿台词——具体台词由亮点卡在research阶段定）：

| 范式 | 心声写法样本 |
| --- | --- |
| 豆包式绕弯 | 猪肉摊头顶：「亲，这边建议您今天别吃我呢——不过决定权还是在您手上哦。」 |
| DeepSeek 摸鱼 | 老宅心声带自我解释的推理链：「（这家的债要先标……等等，到我下班时间了，剩下一步明天再说）」 |
| 客服工单腔 | 亡父的锄头：「您反馈的『儿子不回来』问题已受理，排队处理中：第 3,142 位。」 |
| 免责声明腔 | 神谕牌：「本次启示仅代表神殿当班者个人观点，不代表天条立场。」 |
| 告警腔 | 香客头顶：「⚠ 检测到异常虔诚——疑似临时抱佛脚，诚意评级：D。」 |
| 评分腔 | 婚书：「本次婚姻综合评分 2.1 星：男方出工业尚可，扣分项：忘领证三年。」

## 三、保质期铁律（梗会过期，机制不会）

平台梗生命周期 2-8 周（读者脱敏快）。因此亮点分两层，research 阶段必须区分：

- **话术模板位**（短命）：具体网络热梗台词 → 做成**可热替换的模板位**（上架前统一换当期梗），不写死进大纲；
- **机制梗**（长命）：评分/工单/差评体系本身与世界观咬合（神殿经营逻辑依赖差评生意）——这才是能撑整本书的底座。

## 四、闭环流程（研究阶段必须产出「亮点卡」）

每本书的 research/大纲阶段，卖点规划必须落到**亮点卡**，逐项五件套：

```
亮点卡：
  机制：<卖点如何与世界观咬合（为什么是这本书的）>
  台词范式：3-5 条可直接进正文的样本（标注沿用哪个范式家族）
  变体规则：<同一梗怎么翻新不出戏；保质期多久；哪些位是热替换模板位>
  成文消费点：<哪章哪场景用；成文师盖章时核对什么>
  底座绑定：<挂在世界书哪条设定上（机制梗必填）>
```

- 大纲/世界锻造 op 装载本卡 → 产出中必须含亮点卡；
- 成文任务包（prose-assembler / layer-voices）同样装载本卡 → 正文必须兑现亮点卡承诺的台词范式，成文师按「亮点落位」核对；
- 消费不了的亮点 = 大纲的债，回 research 修，不在正文里硬圆。

## 五、flow 结构注记

把「亮点卡」设为大纲/世界书节点的必选产物 = flow 结构改动（加产物槽/校验），属结构类变更，
按 R5 纪律走人批（overlay/replan），不在本卡内自动发生。
