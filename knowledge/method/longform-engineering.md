# 长篇工程方法

**标尺**：长篇的敌人是「上下文有限 + 无计划地写」。四个已验证的工程机制，全部映射到本库既有件上。

## 一、细纲节拍（章 → 3-6 拍，中文网文实践标配）

每章先出细纲：3-6 个场景节拍，每拍五行卡——**地点 / 在场人物 / 冲突或事件 / 情绪值走向 / 拍末钩子**。正文按拍逐段生成，一段一拍；拍与拍之间允许时间跳跃（果断跨越，`kb/deconstruct/style-learning` §情绪笔墨密度）。
- 判定：拍数 <3 = 章没有地形；>6 = 章塞爆该拆；
- 每拍的钩子是「拍末小钩」，章末拍必须是章钩（状态改变）；
- 细纲先落盘（台账/章纲文件），可编辑后再生成——细纲是人与 AI 的接口，跳过细纲直接生成 = 放弃控制权（DOC 的核心教训）。

## 二、层级大纲贴附（DOC）

生成第 N 拍时，上下文里挂：全书一句话 → 本卷一句话 → 本章一句话 → 本拍五行卡——**只挂链上这一条路径**，不整本塞入（层级前缀）。写完自检：本拍是否推进了本章那句话？没推进 = 删或重写。

## 三、双层记忆（RecurrentGPT → 本库映射）

| 论文概念 | 本库对应物 |
| --- | --- |
| 短期记忆（最近段落要点） | 上一拍的「拍末状态」两行（谁在哪/刚发生什么） |
| 长期记忆（设定/大纲/人物） | World Bible + 章功能序列 + 人物卡 |
| 下一段计划 | 下一拍的五行卡 |
| 循环续写 | 台账滚动（`kb/continuity/state-ledger` 五类：人物状态/在场物品/知情范围/到期伏笔/长期承诺） |

写作前置：从台账切片生成「本拍已知信息卡」——人物此刻知道什么/手里有什么/欠着什么（`skills/novel-chapter` 处境校准同源）。

## 四、递归重提示与回环修订（Re3 / sumeru）

- **递归重提示**：某拍写崩（情绪断裂/人物出戏）时，不整章重写——把「该拍前两拍摘要 + 人物卡相关切片 + 重写指令」重新组包重写该拍，缝回原文；
- **大纲↔正文回环**：审查发现剧情矛盾/设定崩坏/重复情节时，轻问题改正文，**重问题回退大纲修订后重写对应章**——只改正文是欠账（sumeru fix-plan 分级）；
- **修订备份**：任何重写前快照留档（本库铁律 7 已覆盖）。

## 五、强度自检（章级）

1. 本章细纲存在且 3-6 拍？
2. 每拍生成时挂了层级大纲路径？
3. 台账切片进了每拍前置？
4. 章末拍 = 章钩？
5. 严重问题是否回退了大纲（而非只糊正文）？
