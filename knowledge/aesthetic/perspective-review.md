# 视角评审协议（红方 v2）

**命题：评审是"人看完想不想继续"，不是指标打分。** 机器能查的（钩子在场、时长、字数、密度计数）全部归断言层（`check_aesthetic_asserts`）；红方只做机器做不了的事——**代入四类人，说人话**。

## 一、四视角定义

| 视角 | 他是谁 | 他怎么表达 | 他在乎什么 |
| --- | --- | --- | --- |
| **目标读者** | 客群画像里的典型人（如 35-50 岁被裁焦虑的男性打工人） | "我就是这种人，第三集他修闸机那里我坐直了/我看不出跟我有什么关系" | 代入感：这故事是不是在说**我** |
| **一般读者** | 路人观众，无预设兴趣，刷到就看 | "开头三秒我没划走/我划走了；中间看困了；结局哦" | 跟不跟得上的钩子与节奏 |
| **资深编剧** | 干过活的同行 | "第二集信息给早了；这个反转铺垫只有一处，回看立不住" | 手艺：因果、铺垫、价值转变、成本 |
| **甲方** | 出品人/平台采购 | "这个卖点一句话说不清；这个题材现在上会不会撞车；成本超了吗" | 卖得动吗：卖点、时机、合规、预算 |

## 二、意见格式（说人话，但可追溯）

每条意见三段式：

> **【视角 · 锚点】** 我看到哪里时什么感受 → **为什么**（用这个视角的在乎来解释）→ **如果改成 X 我会[继续看/买单]**（不写"安全系数不足"这类词）。

纪律：
1. 每条意见仍须挂 `kb_ref`（判断依据来自知识条目）——**人话表达，标准驱动**，不是口味点评。
2. 四视角**各自独立出具意见**，允许互相矛盾（读者嫌慢、编剧说该慢）——矛盾本身就是信息，由红方汇总呈现，不做和稀泥合成。
3. 同一剧情不同人群理解不同时，必须并列呈现（例：穿书设定，男频老读者视为套路疲劳点，泛观众视为入坑钩子——并列，交甲方裁决）。

## 三、判定与打回

- 每视角给出自己的结论：**追 / 犹豫 / 弃**（读者系）或 **过 / 打回**（编剧/甲方系）。
- **共识判定**：任一"弃"即整段打回重做；"犹豫"须附条件（改成什么就追）。
- **打回必须指认根因阶段**：问题出在调研（方向/人群就错了）、结构（框架单薄）、方案（人设/大纲）还是成稿（执行）？——红方只指认，不越权改稿。
- **级联规则**：根因在第 N 阶段 → 第 N 阶段重做，其后所有阶段产物顺延失效重审（流程的推演有逻辑，不是哪坏修哪）。

## 四、"不确定因素"提案（反单薄机制）

框架正确 ≠ 作品成立。**正确框架 + 直白执行 = 单薄**。红方在"框架可行但单薄"时，必须提案**不确定因素注入**：在人物前史、身份层、世界观规则上加入至少一个反转既有认知的变量（例：老年复仇框架 + 她曾是黑道大小姐 / 真假千金互换 / 穿书转世自知剧本），使同一框架长出不同作品。提案格式沿用 `kb/aesthetic/unreasonable-highlight`，但表述用视角语言（"如果她是黑道大小姐，第一集保安拦我那段我一定二刷"）。

## 五、与断言层的分工

| 层 | 管什么 | 谁 |
| --- | --- | --- |
| 断言层 | 钩子事件、时长、字数、密度计数、格式、合规——机器可查 | `check_aesthetic_asserts` minitool |
| 视角层 | 代入感、节奏体感、铺垫手感、卖点锐度、时机——机器查不了 | 红方四视角（本协议） |

红方意见书 v2 结构：四视角意见（各若干条，三段式）→ 共识判定 → 根因阶段指认 → 不确定因素提案（如适用）。
